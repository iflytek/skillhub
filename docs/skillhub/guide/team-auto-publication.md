# 团队内自动发布

团队内自动发布（team-only automatic publication）是 `TEAM` 命名空间中授予单个普通成员的权限。授权后，该成员在本空间内满足条件的团队内可见提交，会在**当前一轮安全扫描明确为安全**之后，由系统自动批准并发布。它不是新角色，不是命名空间开关，也不是令牌权限范围；审核任务照常创建并保留，只是批准决定由系统记录。

## 适用范围

| 情形 | 是否适用 |
| --- | --- |
| 新技能首次发布即为团队内可见（`NAMESPACE_ONLY`） | 适用 |
| 已为团队内可见的技能提交新版本，目标可见范围不变 | 适用 |
| 私有技能申请改为团队内可见（独立可见范围申请） | 不适用，按原审核流程 |
| 上传新版本时目标可见范围与当前不同（例如现有私有技能以团队内可见上传） | 不适用 |
| 公开发布、全局提升或任何扩大可见范围的操作 | 不适用 |
| 复用发布逻辑的重新发布 | 按上述同一规则判断；目标可见范围变化时不适用 |
| GitHub 同步、技能套装与 Bundle 导入编排 | 不适用，保持原规则 |
| `GLOBAL` 命名空间、个人命名空间 | 不适用 |

权限覆盖该成员在本命名空间内的网页提交，以及该成员持有的所有具备提交能力的 API Token。网页与 Token 提交遵守同一策略；Token 仍须具备提交能力（当前为 `skill:publish`），只读 Token 无法上传。本功能不表示“某种 Token 预设永远不需要人工审核”。

## 授权与撤销

1. 以该命名空间的所有者（Owner）或空间管理员（Admin）身份登录网页。
2. 打开“成员管理”。`TEAM` 命名空间的成员表会显示“团队内自动发布”列：普通成员显示“已授权”或“未授权”，所有者和空间管理员显示“不适用”。
3. 在目标成员行点击“授权”或“撤销”，阅读确认弹窗中的范围说明后确认。

只能通过网页会话操作。对应接口为 `PUT /api/web/namespaces/{slug}/members/{userId}/team-auto-publication`（`/api/v1` 同路径），请求体 `{"granted": true}` 或 `{"granted": false}`，须带会话 Cookie 和 CSRF 头。任何 API Token（包括带 `token:manage`、`skill:delete` 等权限范围的 Token）调用该接口都会被拒绝；普通成员也不能给自己授权。

授权的边界：

- 默认未授权，只能授予 `MEMBER` 角色；不改变成员角色，不赋予审核、删除、空间管理、私有内容确认发布或其他命名空间的任何权限。
- 冻结或归档的命名空间中成员管理为只读，不能授权或撤销。
- 每次从未授权变为已授权都会生成新的授权标识；重复授权不会生成新标识。
- 授权、撤销及因角色变更、移除成员、所有权转让、账号合并导致的撤销，都会写入审计日志，记录实际操作者以及变更前后的授权标识。

## 提交之后发生什么

1. 成员提交符合范围的版本时，系统在审核任务上记录当时有效的授权标识。授权只影响授权之后的新提交，已在审核中的提交不会被追加资格。
2. 版本照常进入扫描（`SCANNING`），在扫描结束前绝不会发布。
3. 当前一轮扫描结束后，系统在同一事务内重新检查：命名空间仍为 `ACTIVE` 的 `TEAM`；提交者仍是有效成员且角色为 `MEMBER`；任务记录的授权标识与成员当前有效授权一致；版本仍在待审范围内，且未被后续上传取代；扫描结论属于该版本**当前一轮**扫描且为 `SAFE`。
4. 全部满足时，任务变为 `APPROVED`，版本变为 `PUBLISHED`，决定方式记录为“系统自动批准”（`SYSTEM_AUTOMATIC`），并记录所依据的扫描任务。审核人一栏为空，不会把提交者写成审核人。
5. 任一条件不满足时，任务转入普通审核：留在待审队列，由命名空间审核人处理，并通过现有的待审通知机制（遵循用户的通知偏好）通知审核人一次。

扫描未启用、执行失败、结论为不安全或可疑、超时、结论未知或已过期时，都不会自动批准。扫描服务暂时不可用时沿用现有的延迟重试；最终失败后任务转入普通审核。

## 撤销、移除成员与重新授权

- 撤销授权、移除成员、角色变更或失去资格时，该成员所有尚未完成自动批准的待审任务立即转入普通审核。正在扫描的任务会继续扫描完成，之后按普通审核流程处理。
- 重新授权会生成新的授权标识，**不会恢复**旧任务的自动批准资格，旧任务仍需人工审核。
- 已发布的版本不会因撤销而下架。
- 吊销 Token、Token 过期或退出登录，不会取消已经被接受的提交；系统也不会以工作进程或更高权限身份重试，从而补上原请求没有的能力。系统不保存明文 Token。

## 在审核页面识别系统批准

审核列表、审核详情的“审核记录”和“我的审核进度”会显示决定方式：

- “系统自动批准”：显示所依据的扫描任务，不显示审核人。
- “人工审核”：显示实际审核人。

回退到普通审核的任务与其他待审任务一样出现在审核中心，审核人按[审核技能与套装](./review.html)处理即可。

## 完成标准与排障

| 现象 | 最可能原因 | 处置 |
| --- | --- | --- |
| 成员行没有“授权”按钮 | 当前账号不是所有者或空间管理员，命名空间被冻结或归档，或目标不是 `MEMBER` | 由有权限者操作；不要修改请求绕过权限 |
| 调用授权接口返回 403 | 使用了 API Token，或缺少网页会话或 CSRF | 改用网页会话操作 |
| 已授权但版本仍待人工审核 | 提交早于授权、目标可见范围不在适用范围内、扫描不是 `SAFE`，或授权已被撤销 | 在审核详情查看决定方式和扫描结果，由审核人按普通流程处理 |
| 重新授权后旧任务仍待审 | 设计如此，旧任务绑定旧授权标识 | 人工审核旧任务，或撤回后重新提交 |
