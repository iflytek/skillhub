# 审核与治理

SkillHub 的审核机制用于保证技能包质量、权限边界和平台治理要求被持续执行。

## 两层审核

- 命名空间审核：由团队管理员处理本空间内容
- 平台治理审核：由平台管理员处理推广、举报和更高层级治理动作

## 常见状态

| 状态 | 含义 |
|------|------|
| `PENDING` | 等待审核 |
| `APPROVED` | 已批准 |
| `REJECTED` | 已拒绝 |
| `WITHDRAWN` | 提交方已撤回 |

## 典型流程

1. 开发者发布技能包
2. 系统触发扫描与审核链路
3. 管理员查看包详情、文件内容和审核背景
4. 做出批准或拒绝决策
5. 提交方根据结果继续发布或修正

## 审核时建议重点查看

- 元数据是否完整
- 包内容是否与描述一致
- 是否存在明显安全风险或越权行为
- 是否符合命名空间治理规则
- 是否需要退回开发者补充说明

## 对提交方的建议

- 发布前先完成最基本的本地验证
- 被拒绝后优先处理审核意见，再重新提交
- 发现问题时及时撤回，而不是等待管理员兜底
