# 技能头像与审核

本页说明技能所有者如何提交头像，以及有权审核人如何处理头像申请。技能头像不包含用户个人头像；图片审核与技能包安全扫描是独立检查。供应商开通、凭据和容器更新由部署方负责，见[配置头像机器审核服务](./avatar-moderation-configuration.html)。

## 前置条件与职责

操作前须登录同一注册中心，确认目标技能及当前账号。技能所有者维护头像，命名空间角色或平台角色不自动获得代传权限。

| 操作 | 执行主体 | 入口与边界 |
| --- | --- | --- |
| 新增、替换或移除头像 | 技能所有者 | 发布页或“我的技能 → 更新”；可只改头像而不创建版本 |
| 审核头像申请 | 对目标命名空间有审核权限的账号 | 原技能审核队列；头像与内容同次提交时共同决定 |
| 调整机器、人工审核开关 | 超级管理员（SUPER_ADMIN） | `/dashboard/admin/system-config`；不在此填写凭据或切换供应商 |
| 接入或切换供应商 | 具有部署权限的操作者 | 在部署配置中选择供应商并注入私有凭据 |

团队命名空间所有者（Owner）及空间管理员（Admin）审核本命名空间；平台技能管理员（SKILL_ADMIN）和超级管理员可审核团队及全局。自审限制沿用[技能审核规则](./review.html)，不得从平台角色推导全部自审权限。有权操作者可撤下头像，但不能代替所有者上传。

## 提交与更新头像

1. 在发布或更新表单选择自定义 PNG/JPEG，在裁剪弹窗调整方形区域与缩放。未选择图片时可正常提交，使用技能名首字母。
2. 确认裁剪并等待上传结束。上传中或失败时不能提交；服务器会重新校验图片并编码为 PNG。上传成功只表示已存入私有存储，不代表审核已批准。
3. 提交后，在“我的技能”或更新页核对本次候选图片及机器、人工状态。候选未生效时，公开详情和列表继续显示旧头像或首字母；不能据此认定提交丢失。
4. 被拒绝后读取原因、修订图片并重新提交。新申请替换旧待审申请，旧审核结果不能覆盖新候选；申请记录继续留存。

更新默认保留原头像。单改头像的移除请求提交成功后恢复首字母；移除与新技能包同次提交时，须等待该申请获批。取消编辑或提交失败不改变现有头像，不设单独的头像管理入口。

## 审核策略与申请关系

头像与技能包同次提交时，共用一张技能申请，由审核人在原详情中一次批准或拒绝；头像不会提前发布。只改头像且需要人工决定时，同样进入技能审核队列，标记“头像修改”，不创建新技能版本。

超级管理员在系统配置中分别管理两个开关，默认机器关闭、人工开启。后台不配置供应商或显示密钥。下表适用于非私有技能的单改头像申请。

| 机器审核 | 人工审核 | 生效条件 |
| --- | --- | --- |
| 关闭 | 关闭 | 提交成功后生效 |
| 关闭 | 开启 | 人工批准后生效 |
| 开启 | 关闭 | 机器允许后生效；阻止或异常不生效 |
| 开启 | 开启 | 先完成机器审核，再由人工决定 |

私有（PRIVATE）技能头像仅所有者可读，直接使用，不运行上述机器或人工审核；扩大可见范围时按目标范围重新审核。头像与技能包共同提交时，无论头像开关如何，均须等待原技能申请的批准。

## 机器结果与人工决定

| 机器结果 | 候选与公开头像 | 后续处理 |
| --- | --- | --- |
| `PASSED` | 有人工审核时仍待审；无人工审核时单改头像生效 | 审核人核对候选和目标申请，不能把机器允许作为内容效果保证 |
| `BLOCKED` | 新图片保持私有，旧头像继续使用 | 有人工审核时可拒绝；认为误判而批准须填写明确理由；无人工审核时所有者可申请人工复核 |
| `ERROR` | 新图片保持私有，不能直接批准 | 部署方排查配置、网络或供应商服务，恢复后重试 |

机器阻止不等于文件上传失败，也不等于人工已拒绝。人工拒绝后，所有者可查看候选与原因；人工批准后须核对当前生效头像，不能仅凭任务文字判断最终图片。

## 输入、重试与保留规则

| 项目 | 固定值或范围 | 生效与限制 |
| --- | --- | --- |
| 上传图片 | PNG/JPEG；不超过2MiB；正方形，边长不超过1024像素 | 上传时由服务器校验并重编码；越界提交被拒绝 |
| 临时上传引用 | 24小时 | 过期须重新上传，不等于已提交候选的保留期 |
| 机器异常冷却 | 1小时 | 错误结果后等待冷却；不得通过重复请求跳过 |
| 自动调用上限 | 同一候选共3次，含首次 | 耗尽后在冷却结束后主动重试或重新提交 |
| 已丢弃候选图片 | 被拒绝、替换或移除后私有保留30天 | 到期由清理任务删除图片，文字记录继续保留；不承诺精确到期时刻 |

申请保留提交时的机器、人工开关和供应商快照，后续改开关不会回写已有申请。已完成的机器结果不自动重跑；供应商变更后，旧候选仍需旧供应商时可能为 `ERROR`，须由部署方与审核人协调处理，或重新提交新申请。

规则依据：[上传与引用](https://github.com/iflytek/skillhub/blob/main/server/skillhub-app/src/main/java/com/iflytek/skillhub/service/SkillAvatarUploadService.java)、[图片校验](https://github.com/iflytek/skillhub/blob/main/server/skillhub-app/src/main/java/com/iflytek/skillhub/service/SkillAvatarImageProcessor.java)、[候选状态](https://github.com/iflytek/skillhub/blob/main/server/skillhub-domain/src/main/java/com/iflytek/skillhub/domain/skill/SkillAvatarCandidate.java)及[头像流程](https://github.com/iflytek/skillhub/blob/main/server/skillhub-app/src/main/java/com/iflytek/skillhub/service/SkillAvatarAppService.java)。

## 部署方如何接入机器审核

每个部署选择一个供应商，凭据在服务启动时读取；后台只能管理审核开关，不能通过保存开关验证云账号权限、网络或额度。接入、轮换与切换由部署方按[配置头像机器审核服务](./avatar-moderation-configuration.html)执行，并使用新申请验证实际调用。

## 完成标准与失败处置

所有者应能在更新页看到本次提交的图片及状态；需要审核的申请应在原技能队列可定位；批准后，公开详情显示本次生效头像。上传完成、机器允许、人工批准和公开头像切换是不同完成标志。

| 现象 | 最可能原因 | 定位手段 | 处置 |
| --- | --- | --- | --- |
| 无法提交头像 | 上传失败、格式越界或引用过期 | 查看上传错误，核对本页输入规则和引用时间 | 重新裁剪上传；不要仅修改文件扩展名规避校验 |
| 公开详情仍是旧图片 | 新候选仍待审或未生效 | 在“我的技能”或更新页比较候选和机器、人工状态 | 跟踪当前申请；不要反复提交相同图片代替查询 |
| 机器结果持续异常 | 配置、依赖或供应商故障 | 更新页读取 `ERROR` 和可重试时间，由部署方核对服务配置 | 故障恢复并过冷却后重试；不要将异常批准放行 |
| 关闭人工后技能包仍待审 | 头像开关不控制技能包审核 | 核对是否同时提交技能包及该申请状态 | 按原技能审核完成内容决定；不要修改数据库强制发布 |
| 认为机器误判但无法生效 | 候选被阻止，需要人工复核或明确理由 | 核对 `BLOCKED`、人工开关和当前复核状态 | 所有者发起复核，有权审核人依据证据处理；不要通过换账号绕过审核 |
