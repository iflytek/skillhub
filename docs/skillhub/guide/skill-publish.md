# Skill 发布与版本管理

本页聚焦“如何把技能包稳定发布到注册中心”。更底层的 API 细节不在这里重复展开。

## 核心能力

- 语义化版本管理
- 标签体系（如 `latest`、`beta`、`stable`）
- 多版本共存
- 文件浏览与下载分发
- 与审核、安全扫描联动

## 发布前准备

建议在发布前先确认：

- 技能包目录结构清晰
- `skill.md` / `SKILL.md` 和元数据完整
- 不包含明文密钥、测试垃圾文件或无关大文件
- 版本号符合语义化版本规范

## 推荐发布流程

### 方式一：CLI 发布

```bash
export CLAWHUB_REGISTRY=http://localhost:8080

# 发布到默认命名空间
npx clawhub publish ./my-skill

# 发布到指定命名空间
npx clawhub publish ./my-skill --namespace my-team
```

### 方式二：Web UI 发布

1. 访问 `/dashboard/publish`
2. 选择命名空间
3. 上传 zip 文件
4. 选择可见性
5. 点击“发布”

## 发布后会发生什么

1. SkillHub 接收并解析包内容
2. 系统创建对应版本记录
3. 若启用了安全扫描，会自动进入扫描链路
4. 若命名空间启用了审核，会进入审核流程
5. 发布成功后，其他成员即可搜索、查看和下载

## 版本与标签

- 新版本通过新发布产生，不直接修改已发布版本
- `latest` 应指向推荐默认安装的稳定版本
- `beta` 适合灰度测试，不建议默认暴露给所有用户
- 发现版本问题时，优先发布修复版本，而不是覆盖旧版本

## 常见注意事项

- 大包和复杂依赖会增加扫描与审核时间
- 命名空间策略可能影响技能是否立即可见
- 已发布版本应视为不可变工件
- 发布前最好先在本地环境完成基础验证
