# DSH 登录态持久化方案

## 目标和范围

个人独立使用的 DSH 桌面版登录一次后，重启应用或重新加载插件仍可恢复当前来源的个人 API Token。默认保存，不新增必选配置或另一套登录流程。继续使用现有登录框、个人设置、账户菜单和 `whoami` 接口；SaaS、自建开源服务使用相同客户端行为，不修改 CLI 或发布规则。持久化方案本身不需要服务端改动；同一 PR 的命名空间管理依赖服务端的 `namespace:manage` 默认权限等改动，见 DSH `0.7.0` 发布说明。

有可信本地 Profile 时保存；没有 Profile 的嵌入式 Host 保持现有仅进程内存行为。不存在跨设备同步、共享 Host 多用户会话、自动续期或 refresh token。

## 已确认的实现依据（实施前基线 `6e97ed1c`）

- `plugins/dsh/src/host/account-credentials.ts` 已按 Profile 和来源保存账户，Windows 当前直接退回内存，POSIX 使用所有者独占目录及文件权限。
- `SkillHubService.refreshSource` 恢复凭据，`accountIdentity` 通过现有 `whoami` 核验；`readSource` 在认证失效时统一清理账户和来源版本。
- DSH 的 `credentials-local` 在本机 0.2.2-rc.1 及已核对 SDK 中将记录直接序列化到 YAML，并未提供 Windows 静态加密。插件 Host 是独立 Node 进程，不能直接调用 Electron Main 专属的 `safeStorage`。
- 因此保留现有 `AccountCredentials` 入口，为 Windows 补充 DPAPI CurrentUser 保护，不引入凭据 SDK 依赖及异步账户调用链改造。

## 保存、读取和隔离

1. 仅在当前来源 `whoami` 成功且请求没有取消、来源没有变化后保存。先完成加密及原子替换，再替换进程内账户；保存失败不显示登录成功，已有账户与文件保持原状。
2. 使用当前 Profile 的 `skillhub-accounts` 目录及规范化完整 Registry 地址的 SHA-256 文件名。完整地址包含部署前缀，测试站、SaaS、自建服务互不借用 Token。
3. Windows 正式文件与临时文件只存版本化密文封装：`{ version: 1, protection: 'dpapi-current-user', ciphertext: '...' }`。明文仍是来源、Token 和最小身份对象，不写入临时文件、设置、浏览器 localStorage、环境变量或日志。
4. DPAPI 的可选熵绑定用途版本、规范化 Profile 路径及完整来源。Windows 使用 `realpathSync.native` 获取真实拼写，不按输入路径大小写或简单转小写计算。解密后继续检查来源、Token 和身份字段。复制密文到另一个来源或 Profile 不能恢复账户。保护边界是当前 Windows 用户，不承诺防御同一用户权限下的恶意程序。
5. 保留 POSIX 旧格式和权限规则，不读取或迁移 DSH 全局凭据仓库。目录/文件拒绝符号链接、非普通文件和超限数据；Windows 不依赖无效的 POSIX chmod 作为加密替代。
6. 明文记录最多 8 KiB，密文封装最多 16 KiB；写入和读取均检查。临时文件采用唯一名称及独占创建，写入成功后原子替换，异常时移除本次临时文件。

   正式和临时记录是单文件，删除使用 `unlinkSync` 并只忽略 `ENOENT`，避开 Node 24.2 在 Windows Unicode 路径上 `rmSync` 的问题。Windows 子进程测试的 stdin 使用 UTF-8 流解码，保留分片中的多字节字符；CI 同时验证最低支持 Node 与当前 Node。
7. 首次成功读取后缓存到进程内存，安装和下载请求不重复启动解密子进程。重启后重新读取并由 `accountIdentity` 验证，不凭保存的昵称直接显示已登录。

## Windows DPAPI 边界

使用系统 Windows PowerShell 与 .NET `ProtectedData` 的 `CurrentUser` 范围，不使用 `LocalMachine`。可执行文件取系统目录中的绝对路径，不通过 PATH 或 shell 解析。

调用采用固定脚本、`-NoProfile -NonInteractive`、`shell: false`、隐藏窗口、10 秒超时和有界输出。外层标准输入 JSON 仅含 ASCII：明文记录先由 Node 编码为 UTF-8 字节，再将数据和熵分别转为 Base64。标准输出也只含 Base64；Node 解码后按 UTF-8 解析。这样不依赖 Windows PowerShell 5.1 的系统代码页，中文、emoji 身份及 Profile 路径不会被转码。Token 不进入命令行参数，脚本错误退出且不打印异常或明文。

系统组件不可用、超时或加解密失败时不降级为 Windows 明文保存。写入失败通过固定 `skillhub/account-storage-error` 告知用户；格式损坏记录视为无可恢复账户，不覆盖损坏文件或加载其中身份。解密子进程或文件读取暂时失败则保留原文件并记为可重试恢复失败，不能与“从未保存账户”混同，也不映射为来源地址无效。

初始恢复失败时仍建立匿名 Registry，公开目录可正常读取。`accountIdentity` 是唯一额外重试读取凭据的入口（首次核验和用户点击“重新连接”）；其他公开读取不得循环启动解密。重读仍失败时返回固定恢复错误，来源版本不变，Query 不自动重试，存储错误期间也不因窗口聚焦或网络重新上线触发解密；重读成功后沿现有账户切换流程轮换来源版本，让客户端重新核验 `whoami`。临时错误不导致来源版本反复轮换或无限重挂载。

## 生命周期和失败语义

| 情况 | 行为 |
| --- | --- |
| 应用/插件重启 | 读取当前 Profile、来源的凭据，执行现有身份核验；有效即恢复 |
| 来源切换 | 使用既有来源版本、取消和缓存清理；切回原来源可恢复其账户 |
| Token 替换验证或保存失败 | 原账户、原凭据保持有效，显示固定错误，不自动重试写入 |
| 服务返回 401/身份不匹配 | 当前进程立即忘记凭据并阻止重新读取旧文件，失效来源版本及私有缓存；尝试删除保存记录；即使删除失败也保留 `AUTH_REQUIRED` 认证清理信号 |
| 403、429、网络超时、5xx | 保留保存凭据，不按退出处理；界面可重新连接，不能以缓存身份冒充已通过验证 |
| 用户退出 | 清除当前进程账户、私有缓存并删除当前来源记录；不影响其他 Profile 或来源 |
| 退出时磁盘删除失败 | 当前进程仍退出并阻止旧记录再次加载，明确提示保存记录未清除，不报告完整退出成功；文件保留时重启可能再次尝试恢复，用户可重试清除 |

`clearAccount` 必须在删除异常时仍刷新账户及来源版本；持久层保留本进程的“已忘记”标记，防止刷新立即读回旧文件。显式退出失败也刷新客户端账户和私有查询。401 清理不允许被磁盘异常变成普通存储错误。

删除失败的提示不能只保存在会被来源版本重挂载的组件局部状态：持久层按完整来源记录删除失败，`getContext` 通过可选布尔字段 `accountClearFailed` 只返回当前来源的失败事实。`CatalogPage` 将此事实传入新的 `AccountWorkspace`，在未登录时也保留提示和“清除保存的登录”按钮。该按钮复用当前来源版本的 `disconnectAccount`，成功后更新上下文、隐藏提示；切换来源时不展示或清除另一来源的记录，过期来源版本必须先拒绝请求。该字段不包含 Token、身份、文件路径或凭据内容。

上下文和身份 Query 调用的是本机 Host RPC，使用 `networkMode: 'always'`；浏览器持续离线时仍能读回退出结果和清理提示，不能被默认联网策略暂停。来源的 `whoami` 仍按实际网络结果处理，不伪造远端核验成功。

界面不新增保存开关。登录核验期间显示等待状态；已保存凭据遇到暂时连接失败时显示错误和“重新连接”，保留登录入口以便更换 Token；核验或本机恢复失败时也提供不依赖远端的“清除保存的登录”。继续使用现有弹窗、按钮、主题和错误文案映射，不返回 Token 或存储文件内容到前端。

## 影响范围

- `account-credentials.ts`：保存格式、权限、缓存、原子替换、退出失败语义。
- Windows 保护 helper：固定系统调用和管道协议，不增加 npm 运行时依赖。
- `host/index.ts`：存储错误映射、失败时仍清理认证状态、身份读取时重试恢复，保留原有来源/取消检查；`CatalogContext` 仅增加可选 `accountClearFailed` 标记。
- `catalog-page.tsx`、`account-workspace.tsx`、`catalog-error.ts`：固定错误、等待/重连、退出失败后的缓存刷新和跨版本清理重试；不改变 RPC 方法签名。
- 凭据、Host、UI 测试，插件中英文 README 与本设计。

## 验收与评审门槛

实施前须由独立子代理审查本方案；阻断项修订后明确通过，再修改产品代码。

- 单测：重建 store 后恢复、双来源/部署前缀、双 Profile、退出、替换失败保留旧值、损坏/超限/格式异常、文件权限和符号链接、读取缓存、删除失败不在本进程复活。
- Windows 真实运行：使用无效于任何真实服务的固定测试 Token，在 Windows DPAPI 下写入；全新 Windows Node 进程恢复中文/emoji 身份和非 ASCII Profile 路径、替换、退出后再启动、跨来源/跨 Profile 复制密文被拒；检查正式及临时文件不存在测试明文。不得用 Linux mock 代替此项。
- Host 测试：跨实例恢复后 `whoami` 成功、401 清理含磁盘失败、403/网络故障保留、无效 Token 替换不覆盖旧账户、首次解密失败后重试恢复且无无限版本轮换、来源/取消竞态沿用现有保护。
- 界面测试：连接失败可重试；按真实 `CatalogPage` 来源版本重挂载验证退出失败后私有缓存清空、提示仍可见、重试成功后新进程不恢复旧账户；切换来源不能清错记录；登录失败保留旧连接。验证账户弹窗的现有明暗主题、键盘和窄屏布局。
- 构建、类型检查、lint、全部插件测试；对应 Windows CI 应执行真实 DPAPI 用例。最后由未参与实现的子代理代码审查，修复已确认问题并重跑受影响测试。
- 如安装本地包，延续当前 Windows DSH 的已授权流程，不把测试夹具当作真实账户的重启验收；真实测试源仍仅为 `https://skill-test.xfyun.cn`，不读取/输出用户 Token。

本设计不声称当前代码已实现上述行为。验证结果随实施报告列出通过、未运行及环境限制。
