# 批量人工审核

审核中心在原有列表中增加复选框和批量操作条，保留每页20条分页与单项详情审核。支持普通上传和 GitHub 同步的技能版本；套件、头像、可见范围申请不支持批量处理。API Token 的审核权限保持不变，不因此开放新的 scope。

## 操作与长列表

- 表头复选框只选择当前页，跨页保留显式选择，每批最多50项。不会自动选择新入队任务；更改筛选或排序前确认清空选择。
- 批量通过/驳回先请求预检查，确认窗列出可操作与不满足条件的任务。弹窗限制在视口内，内容区独立滚动，头尾保持可见。
- 关闭弹窗后，焦点返回发起操作的按钮；若原按钮已消失或暂时禁用、无法接收焦点，则返回列表结果标题，便于继续键盘操作。
- 批量通过要求版本仍为待审且最新活动安全扫描已完成、结论 SAFE、isSafe=true、无失败原因。无扫描记录的历史任务需进入详情按原规则单独处理；不会修改历史数据或放宽单项流程。
- 同一技能已有更新版本发布时，较早版本不再通过批量入口发布，保留待审并提示进入详情处理，避免批量选择次序回退当前版本指针。
- 批量驳回需要统一原因；原因和意见最长2000字符。
- 操作完成显示每项结果，未纳入项继续保留。超时不自动重试；先刷新任务状态，再由用户明确选择下一次操作。状态核对结果不代表本次审批者完成了该操作。

## 增量接口

会话认证与既有 CSRF 防护适用于两个路径前缀 `/api/v1/reviews` 和 `/api/web/reviews`：

- `POST /batch-preview`：预检查，不修改审核状态。
- `POST /batch-decide`：逐项执行决策。

请求：`{ "ids": [1, 2], "action": "APPROVE", "comment": "checked" }`。action 仅为 APPROVE 或 REJECT；ids 必须为1至50个不重复的正整数。预检查通过不代表保留了执行权限或锁。

返回使用既有 ApiResponse；`data.items` 中每项包含 `id`、`outcome`、`reason`、`message`。outcome 为 READY（预检查可执行）、APPROVED、REJECTED、SKIPPED（未处理，附原因）或 UNKNOWN（执行结果需进一步核对）。整体 HTTP 200 不表示所有项目成功；参数或认证失败仍使用现有 HTTP 错误响应。

## 安全、事务与并发

- 身份取自认证上下文，不接受请求体里的审核人。每项刷新空间成员权限与平台角色；等待资源锁后重新检查，不信任前端预检查或过期的请求属性。
- 执行前锁定技能和版本并刷新实体，再复用原审核链路。已有审核状态条件更新保证重复或并发决策只有一次有效状态迁移。
- 每项使用独立事务，共同提交审核状态、版本状态、发布指针、审计和事务内通知。单项失败不回滚其他成功项。提交失败在事务边界外转成逐项结果。
- GitHub 现有 BEFORE_COMMIT 来源/许可证复核与 AFTER_COMMIT 通知监听器继续生效；批量入口不绕过它们。预检查不能覆盖所有提交时业务约束，提交期间仍可能部分失败。
- 批次串行执行，每项事务超时10秒；总处理超过25秒后，其余未开始项目返回 SKIPPED，避免无限持锁。没有自动重放机制，也不创建重复审核任务。

## 验证边界

仓库测试覆盖参数与认证边界、普通成员越权、逐项事务、扫描阻断、前端跨页选择上限及超时不重放。PostgreSQL 测试验证单项失败后的状态/指针/通知/审计回滚，以及双请求竞争只有一次发布、审计和通知。真实浏览器和部署验证结果应以对应 PR 的验收证据为准；测试存在不等于已运行。
