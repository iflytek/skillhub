# 按任务组织页面与组件

2026-11-09 用户授权的未发布工作修订。替代 management-density.md；不改变发布版本号，不把产品限定为管理后台。机器核验见 task-composition.json。

## 任务决定布局，不由用户角色决定

| 任务 | 布局 | 信息与动作 |
|---|---|---|
| 阅读、了解 | 阅读列最大760；不要求侧栏 | 正文14–16，减少控件；突出内容与下一步 |
| 浏览、发现、选择 | 最大1152，响应式卡片或列表 | 图片/标题/描述/必要元信息；卡片间距16，区块24 |
| 协作、编辑、处理列表 | 灵活内容列；可选240侧栏 | 搜索、筛选、表格与详情围绕当前任务组织 |
| 填写、确认 | 清晰字段顺序，输入32 | 校验提示、当前选择、明确提交结果；保留返回路径 |

240侧栏 = --sh-space-12 × 5，只是工作区外壳的一种选择，不覆盖全站320基线。仅一组菜单时无需侧栏；保留产品品牌与必要全局入口，但不得机械堆叠全局侧栏、局部侧栏、多排Tab。

## 密度与尺寸

- 页头主操作与表单32px，字13，左右12，图标16，gap8。
- 搜索/筛选工具栏、分页、轻量次操作28px，字13，左右10；行内动作24px，字12，左右8，图标14。
- 普通徽标24px；表格状态使用 `.badge--sm` 20px（--sh-space-5），均字12、左右6、圆角6、内容宽。避免缩小正文来制造紧凑感。
- 数据表表头36，单行40，双行52；横向padding12，纵向8，正文13，辅助元信息12。长内容自然扩展，必要信息不可截没。
- 页头20/600、区块与卡片标题16/600；正文13或14，辅助信息12。不要仅设置字号而忽略字重层级。
- 一组动作内gap8–12，同一内容分组内部gap8–16，区块之间24，卡片间16。留白应表达分组；不得用固定大块填满画布。
- 按钮用内容宽度；区分主按钮、描边、文字/幽灵动作。输入与字段选择器可满宽，短操作按钮不跟着字段拉伸。

## 信息与导航

先写出用户当前要找什么、判断什么、完成什么，再选择列表、卡片、表格、表单。统计必须帮助判断或提供下一步，不能只用于填满概览。

同一对象仅保留一层局部导航。空间示例可以使用“概览 / 技能 / 成员 / 加入申请 / 邀请链接 / 技能审核 / 设置”，按权限和空间类型裁剪；这是一种页面组合，不是全产品必选菜单。窄屏采用当前分区选择器或可滚动导航，保持字段完整。

页头集中对象名称、状态、简短描述与元信息，避免跨多块重复展示。筛选和结果紧邻；详情中的辅助说明靠近对应操作。

## 功能完整性与状态

添加成员保留 userId / 昵称 / 邮箱模糊查询（至少2字符），目标设计包含完整手机号精确查询（产品落地须核对实际接口、权限和脱敏要求），保留手动输入userId。搜索方式使用字段选择，不再叠加一排导航。结果显示昵称、邮箱、userId；手机号模式显示必要脱敏结果。明确账号与角色后添加。

状态色使用现有tone弱底/前景成对token：正常/有效/批准/使用成功为success；待处理/过期为warning；拒绝/失败为danger；替换/管理角色为info；归档/普通角色为neutral。不能为了装饰任意换色。

## 动态页面复用

以下接法仅适用于独立 HTML 原型；React 产品复用现有 Radix Select，见 `product-adoption.md`。HTML 下拉采用 `.select` / `.select-trigger` / `.select-content` 结构与 `assets/select.js`，不要用原生 select 冒充自定义组件。动态插入组件后调用 `window.SkillHubSelect.init(root)` 或 `initAll()`；原有自动初始化保持兼容。页面监听 `select:change`，数据与业务动作仍归页面负责。

表格通用修饰类为 `.data-table--task`，`.data-table--management` 仅为兼容别名。

## 核验顺序

1. 业务信息和已有能力是否完整、当前任务是否清楚。
2. 导航是否重复、首屏比例和内容宽度是否合理。
3. 组件真实尺寸、字号、内边距、状态色是否来自本库。
4. 长名称、空/加载/失败、展开菜单、窄屏、操作完成态是否可用。
5. 浏览器/原生导出视觉检查优先；节点回读与重建预览作为补充，分别记录边界。

## 内容收合与留白（本轮补充）

- 空白必须表达分组或阅读边界。不得固定拉高弹窗、结果区域或卡片，以填充截图画布。
- 页面头部使用紧凑对象摘要：面包屑、名称与状态、一行可换行的标识/角色/简短描述、一层导航。组内间距8；工具栏与结果16；独立区块16–24。
- 四列以内的短记录和少量选项可采用960内容组（1152 − 48×4），页面上下文导航仍对齐同一外壳；富数据列表保留1152。不能让所有短内容都强制撑满最大宽度。
- 命名空间浏览卡片在足够宽的桌面采用三列，1280以下两列，640以下单列。卡片padding16、内部gap8、次操作28；不设占位描述的min-height，不丢失标识、角色、状态或描述。
- 页面弹窗使用 `.dialog-layer--viewport` 固定到视口，遮罩消费现有scrim token；预览画廊内的旧定位不受影响。
- 弹窗默认480宽、padding20、内容自然高度；复杂长表单和需要辨认身份的成员选择可采用640变体。桌面由标题、字段、结果和按钮形成实际高度，最大高度只用于防止越出视口。无结果时不保留结果占位高度。
- 表单组合只设置一层纵向间距：字段内部8，字段组之间12；当.field已位于grid/flex分组内，其margin-top为0。描述与字段、字段与footer之间16，不叠加父gap与子margin。
- 原型示例：双候选账号查询约580高，单候选手机号约500高，审批详情约450高；这些是当前内容的结果，不是组件固定高度。
- 少量记录后的页面背景可以自然留白；不能通过放大行高、拉伸卡片、编造记录或添加无关统计填满视口。Figma静态画板展示内容与必要导航，不统一设为1120高。

## 成员选择弹窗 · 舒展变体（历史方案，已被下节替代）

机器参数 `contentFit.maxMockAccountHeight` / `maxMockPhoneHeight` 保留为旧示例的兼容字段，只描述历史640单列表内容，不是960工作区的高度上限；当前成员查找几何以 `memberSearch.presentation` 为准。

本节保留设计过程；当前成员查找任务采用下节 960 工作区，不再以本节 640 单列表作为实施依据。其他任务确需 640 表单时按其实际内容选择，不影响默认 480 弹窗。

当需要同时辨认昵称、邮箱、userId 并确认角色，采用640宽（已有container-form token）、padding24（space-6）的成员选择变体。标题20/600；身份卡片padding16、头像40、姓名14/600，辅助信息12；候选间距8，分组16–24。保持表单/主操作32、行内选择24，不通过放大普通控件获得“大气感”。选中状态使用primary-soft弱底、focus边框和对勾/文字，不另造品牌色。

此变体仍按内容自然收高，不为无结果预留两张卡片位置。搜索方式、账号查询、手机号精确查询、必要身份字段、角色说明和手动userId必须完整；手动入口置于角色说明之后。移动端宽度减32，padding20，搜索方式单独一行、输入和查询按钮同排；头像降到32，长文本换行。

此为特定身份选择任务的组合变体，不改变其他确认弹窗的480默认宽度，也不将640变成所有弹窗默认。

## 成员查找工作区（2026-11-10 本轮用户修订）

当需要搜索并浏览较多候选，使用成员查找工作区，替代上轮640单列表方案。桌面960宽（1152−48×4），最大720高（48×15），并限制为视口高度减48；搜索与结果在左，288宽（48×6）的身份/角色确认在右，底部提交固定可见。高度用于承载持续选择任务，不沿用普通确认弹窗的自然高度规则；默认480确认弹窗不变。

搜索区内间距8；区块24，左右主区padding32/24，侧栏padding24；标题20/600，候选姓名14/600、辅助12、头像40，已选身份头像48。表单和主操作仍32。候选结果区域独立滚动，查询与底部操作不随结果滚走；每次只选一个账号，避免新增后端未支持的批量添加。

当前候选接口返回最多10条、没有分页总数，原型明确提示“最多展示10位，请细化关键词”，不虚构总页数或加载更多能力。确认区保留昵称、邮箱、userId、加入角色和作用范围，手动userId放在确认区。未选择账号时提交禁用；重新查询保留已选账号，显式取消选择才清除。窄屏改为上下分区，结果最高240独立滚动，整体内容可滚，标题和提交保持可达。
