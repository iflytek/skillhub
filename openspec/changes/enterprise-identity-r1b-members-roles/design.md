## Boundary

Organization 权限始终由目标组织的 ACTIVE Membership 和组织角色决定；平台 `SUPER_ADMIN` 不能绕过。控制器只绑定参数，应用服务编排既有 `OrganizationMembershipService` 与 `OrganizationRoleBindingService`，租户列表由查询仓储提供。所有写操作保持同事务规则和现有审计链路；不在 API/日志返回身份源 subject、Secret 或请求体。

组织所有者可以管理成员。登录连接与密钥轮换分别使用 `MANAGE_LOGIN_CONNECTIONS` 和 `ROTATE_LOGIN_SECRETS` 权限。角色授予必须以另一次显式请求完成，目标必须是本组织 ACTIVE 成员。成员和角色写入按组织串行，事务获得锁后再检查当前权限和重复请求。最后一个 ACTIVE owner 绑定受到保护。

组织列表为有权查看成员的用户提供明确的「查看成员」入口。普通成员可以看到自己所属组织的摘要。成员页显示当前组织、成员及授权范围内的角色。添加成员和授予角色各自在弹窗内完成。待添加的用户可从个人设置复制用户 ID，由管理员填入。成员 API 只提供展示和管理所需的信息，平台账号邮箱不写入新建的手动成员记录，也不出现在成员响应中。

授予角色时，弹窗显示目标成员并要求管理员主动选择角色。撤销前显示成员和角色。提交失败时保留弹窗供用户重试；账号或组织切换时关闭原弹窗并清除草稿。查询缓存按账号隔离，管理操作成功后重新读取权限与成员信息。只有实际状态变化才写授予或撤销审计。页面按响应里的权限显示操作，服务端执行最终鉴权。登录页和 `returnTo` 沿用已有实现。

本批无新数据库表或迁移。回滚应用版本只移除新管理入口，不删除已写入的成员、角色和审计；若已授权新管理员，回滚后仍可由既有领域能力读取，后续恢复必须保留数据。
