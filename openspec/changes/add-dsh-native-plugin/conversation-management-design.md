# 对话管理已安装技能

状态：共享核心与 Host 的既有实现及验收保留；按技能分组的 Client 增量已完成本地实现与双 RC 验证。各候选的实际检查、双 RC 宿主和真实模型结果分别记录于 verification.md。

## 目标与范围

用户在 DSH 对话中查询当前 Registry 管理的安装、检查更新、指定版本更新及确认卸载。按钮与自然语言共享 Host 校验和安装核心。首期单技能操作，不做批量、跨来源接管、强制覆盖、启停、SaaS 或发布。

## 已确认产品交互

1. 查询按技能身份合并展示名称；单份安装显示范围，多份安装在组内选择范围并联动版本。正常突出使用，检查更新/卸载收进更多菜单。明确只包含当前来源；更多结果按需展开，不宣称是本机全部技能。
2. 模糊名称或结果序号必须绑定有效结果；多个安装位置先选择，不由模型猜测。
3. 检查更新展示当前和目标版本；失败不当作无更新；无法确定版本顺序时展示不可升级原因，不自动选择替代版本。
4. 更新和卸载均须 Host 发起用户确认，优先输入框附近的原生问题界面；不可用时使用对话确认卡，不能自动执行或让模型伪造确认。
5. 确认后原操作卡显示进行中和最终结果，不刷新整个页面，不强制打开详情。历史回执不等于当前安装状态。
6. 用户取消不写文件；执行期间重复点击不重复执行；来源、会话、根目录或安装记录改变后失效并重新核验。
7. 本地内容变化阻止更新及卸载；其他来源或归属未知安装不认领、不修改。列表存在检查不冒充完整内容核验。
8. 结果仅展示技能、范围、版本与核心状态；详细诊断按需展开，不默认展示内部引用、路径、操作 ID 或来源 URL。

## 已确认：按安装位置更新

用户选择方案 B：同一技能可在当前用户和不同项目保持不同版本。一次对话更新只改变用户确认的那个安装位置，未选位置的文件、版本、来源及归属保持不变。多位置不是首期拒绝更新的理由。

库存必须能表达每个安装位置的版本和指纹。Host 列表、更新比较、预检、确认、文件提交、库存提交和恢复均使用同一目标身份。页面与对话共享行为；CLI、同步和套件处理必须理解该模型，不能只修改对话入口。

### 兼容与恢复约束

- 旧库存可读，转换前保存可验证的恢复基准；不得仅为读取而静默改变真实安装版本。
- 对已在不同位置形成不同版本的安装，不能通过恢复旧库存文件假装完成降级；库存与文件必须一致。
- 旧消费者不理解新模型，须通过真实旧版本测试明确读取/写入行为；不得把 schemaVersion 字段当作旧代码会自动遵守的保护。
- 不同目标并发更新不得互相覆盖库存；同一目标串行化或明确拒绝。共享归属和本地内容变化仍按原规则保护。
- 断电、进程退出、文件提交后响应丢失等恢复只能处理本次目标，不能重放成全位置更新。

### 版本语义

本轮支持指定可升级版本，保留现有版本比较约束。当前实现拒绝降级、无法排序以及同版本不同内容；因此早期交互描述中的“切换版本”不能被当作已支持任意版本替换。UI 应展示明确的不可升级原因，不通过改按钮文案绕过核心。

- 列表完整性和不可读状态不丢失，不将未知等同未安装。
- 最新/指定版本、不可下载版本、非 SemVer、无更新与请求失败分别覆盖。
- 确认、取消、重复点击、旧引用、来源切换、会话切换和本地修改都有行为测试。
- 查询结果、确认目标、实际文件与库存、操作回执一致。
- 在当前声明支持的两个 DSH RC 上分别验证原生确认与回退卡、历史结果、窄窗口和多条目；真实模型调用与手动工具测试分别记录。
- 插件 build/typecheck/lint/tests、相关共享核心回归、OpenSpec 严格校验通过后方可报告实现完成。

- 同一技能用户级 v1 与项目级 v2 并存；只更新项目到 v3，用户级内容和记录保持 v1。
- 不同项目并发更新、旧库存读取、旧消费者访问和恢复后的完整性均须有独立证据。

## 库存迁移方案

采用显式第二版库存模型：技能来源坐标与每个安装位置的版本、指纹、安装时间和归属分离。不能保留一个有歧义的 item.version 并让部分消费者继续使用它。所有读取者使用共享解析/投影函数，写入在已有库存锁及目标锁下执行。

库存继续使用单一 inventory.json，以显式 schemaVersion: 2 区分；读取旧格式时仅投影，第一次写入前在同一锁域内迁移并保存不可变备份。不维护第二份可写库存或双文件迁移标记。协调升级已是使用前提，额外文件不能保护技能文件免受旧程序写入，不为此引入双权威恢复状态。

迁移流程：在统一锁顺序下检查旧库存、未完成操作和目标身份 → 保存原始字节及摘要备份 → 把组级版本、指纹和继承归属展开到每个目标 → 验证新格式 → 临时文件原子 rename 提交。提交前再次核验旧库存未变化；提交失败按实际文件判定结果，禁止猜测成功。旧未完成操作必须先使用兼容恢复路径处理，或阻止迁移。

已确认兼容边界：启用本功能要求同一主机共同管理技能的 CLI 同步升级；旧 CLI 与新插件混用不能保证安全。源码证据表明旧 InventoryStore 不检查 schema，部分 sync 删除流程还可能在库存写入前移动目录。必须实测选定历史消费者，并明确区分“拒绝写入”与“已修改文件后报错”。

在两个位置形成不同版本后，回滚插件或库存格式前应停用写入并核对实际文件；不能仅恢复旧库存备份。版本一致性恢复或导出方案须在实现前定义，不承诺一键降级。

## 最终安装范围交互

- 新安装默认当前用户；普通流程不要求先理解或选择范围。页面保留安装确认，对话明确安装请求省略范围时由 Host 使用用户级默认，模型不能擅自选项目。
- 项目级安装入口置于高级选项；用户明确要求当前项目时仍支持，必须有可信项目根。无项目根不得回退到用户安装。
- 查询和管理仍展示已有项目级安装，不自动迁移、不隐藏、不清理。
- 更新或卸载唯一匹配安装时直接准备该安装的确认；多份且用户没有明确目标时才提供选择。默认用户级仅用于新安装，不能用来猜测更新/卸载目标。
- 更新、卸载始终经过真实用户确认；确认展示技能、当前/目标版本、实际范围，不能把自然语言定位目标当成完成确认。
- 同一技能不同位置保持不同版本；只改变选定位置，其他位置文件、版本、时间和归属保持不变。
- Desktop 兼容为独立任务，本轮继续针对已声明支持的宿主基线验收，不宣称覆盖旧 Desktop。

用户已接受共同管理这些技能的 CLI 配套升级要求。DSH 插件内嵌共享核心，普通 DSH 用户无需单独安装 CLI。发布版本号和真实旧消费者矩阵以发布前验证为准；迁移保护不能阻止任意旧程序直接修改文件。

## 持久化与操作日志契约

库存 v2 使用 schemaVersion: 2、records 和 suites。records 按 registry/namespace/slug 分组，target 保存 agent、rootDir、installDir、installedAt、installedBy、version 和可选 fingerprint。组级不再保存可用于执行判断的 version/fingerprint；旧缺失指纹保持未知，不通过迁移伪造完整性。现有套件成员固定版本语义不变。

读取旧库存时保留原文件，只在内存中将组级版本、指纹和继承归属展开至目标。第一次写入前，在旧库存锁路径下验证并保存原始字节备份，再原子替换 inventory.json；临时文件和备份不会成为另一权威。新客户端拒绝未知格式。备份命名按原内容 SHA-256 区分，相同备份必须校验一致，不能覆盖冲突文件。

操作日志需显式区分 v1/v2，不能直接把历史日志强制转换成新类型。终态 v1 日志继续可读；未完成 v1 操作需在 v1 库存上先恢复，遇到 v2 库存不能用旧快照覆盖，应保持待恢复。CLI 无法发现全部 DSH Host 的日志目录，迁移前要求停止旧写入进程、由对应宿主处理未完成操作；不声称存在全局自动检查能力。

按位置 CAS 比较来源、规范化路径、版本、指纹、安装时间、归属及重叠路径认领；提交时在最新库存中仅合并所选目标的变化。其他目标并发更新必须保留；同一目标冲突则串行化或拒绝。空目标也需要缺失基线，不能覆盖并发新增安装。保持目标锁到库存锁的统一顺序，迁移预检不得持库存锁等待目标锁。

v2 恢复只比较和恢复本次目标的 before/after，其他位置的新状态保留。未选目标的本地修改或 Suite 归属不使其被连带修改；选中共享目标仍阻断。进程中断与断电耐久性需按实际文件系统行为分别描述，不能把原子 rename 当作所有断电场景保证。

## 模型结果与用户提示

多位置选择使用原生问题界面（可用时），每次只选择一个安装位置，不推荐批量。模型工具结果不包含来源 URL、确认引用、路径或原始诊断；所需内部定位引用仅用于后续工具调用，不应复述给用户。

`accepted` 明确表示真人批准已经完成、操作已经提交；模型不得再次询问是否执行或再次提交变更，应查询原操作再报告结果。`awaiting-confirmation` 引导用户操作已有确认卡；`cancelled` 不自动重试。这些引导减少模型误解，文件写入仍由 Host 的精确计划、真人确认和幂等记录保障。

CLI 直接安装覆盖、升级、删除和同步清理共享目标均核验 Suite/非单一 direct 归属，`--force` 不绕过；Suite 自身使用既有管理流程。目录重叠包括规范化后的父子关系，不能只检查路径相等，也不将同前缀兄弟目录误认为重叠。


## 人工评审补充：结果密度与历史按钮

查询安装、检查更新、操作回执使用不同信息层级：安装查询保留紧凑列表；检查更新仅突出技能/范围、当前与目标版本以及更新动作，不复制使用/卸载等列表工具条；更新/卸载和操作查询用简短状态条，不重复大尺寸技能卡。成功结果不展示查询或刷新按钮；仅处理中或失败/未知时提供必要的查询或重试。正常回执不附技术说明和诊断折叠入口，必要告警与恢复提示仍显示。

列表/检查结果属于原查询时刻。升级、卸载、来源或会话变化可能使旧引用失效；Host 拒绝是正确保护，但 Client 不得继续显示可反复点击的失效写入动作或只有无法处理的泛化错误。应明确提示记录需刷新，提供显式只读刷新入口。刷新后的当前查询结果替换该工具卡的显示内容，标明已刷新；不在旧安装条目中嵌套或追加另一份完整列表，原工具历史数据仍保留。刷新仅展示新查询结果，不把旧版本的更新/卸载意图自动转移到新引用；后续动作重新由用户选择并确认。使用技能同样不能把历史版本自动替换为当前版本。

本增量按新旧引用分别实测使用、检查更新、更新和卸载；包含取消、确认、重复点击、刷新不写入、历史回执重载以及实际文件/库存不变的核验。


### 对话结果密度约定

- 正常安装列表不常驻“刷新安装状态”。仅记录失效或读取失败时显示短提示与“重新查询”；仍为显式只读行为，不自动重绑或重放变更。
- 安装条目使用平铺紧凑行：技能名、版本、安装范围、可用操作；不为每条套多层大卡片。长名称可换行，窄屏操作允许换行。
- 检查更新保留一次技能身份、范围、版本变化和更新按钮；已是最新版本时仅显示结论，不留下空操作区域。
- 更新、卸载及操作查询的终态回执采用简短状态行，不重复旧版本、技能身份、完成说明或技术诊断入口。必要的范围信息保留以区分同名技能的不同安装。
- 加载、错误、告警及恢复未完成必须可辨识，不能为压缩高度伪装成成功。正常内容不靠隐藏溢出或固定高度截断实现压缩。


## 已确认：按技能分组的对话交互

状态：用户已批准按技能合并方案 A，正式实现与本地验收已完成。下文取代早期按安装记录逐行展示的布局规则，底层按位置管理契约不变。

当前紧凑列表仍按安装记录重复显示技能。采用方案按来源 + namespace + slug 分组，仅显示一次技能身份；有两份安装时在组内选择当前用户或当前项目，单份安装只显示范围文本。位置选择切换对应版本和操作目标，不合并底层安装记录。全局范围 Tab 仅作为历史对照原型保留，不纳入正式实现。

正常查询突出“使用”，低频检查更新、卸载放在更多菜单；已明确更新或卸载意图时直接显示对应操作确认，不再重复完整列表。多个位置且用户未明确目标时先选择，不将展示默认值当作更新或卸载授权。确认显示准确技能、范围及版本，取消保持原状。不同来源同名技能不能合并或被当前来源接管。

原型覆盖矩阵：

| 场景组 | 用例 | 评估重点 |
| --- | --- | --- |
| 查询 | 空、单用户、单项目、双份同版本、双份不同版本、多技能 | 身份不重复、范围与版本明确，正常不展示刷新 |
| 选择 | 模糊同名、多安装位置、明确位置 | 只在有歧义时要求选择，目标与操作绑定 |
| 使用 | 有案例、无案例、取消 | 案例或草稿流程保留，不自动发送 |
| 更新 | 可升级、最新、指定较新版本、不可下载、不可排序、降级拒绝 | 不把失败当作无更新，不给无效更新按钮 |
| 确认 | 更新/卸载确认、取消、重复点击、切换位置 | 一次仅改变明确目标，取消不写入 |
| 结果 | 处理中、成功、失败、结果未知、告警或恢复中 | 核心状态简短，未知不显示成功或直接重复执行 |
| 保护 | 本地修改、文件缺失、共享归属、其他来源 | 不出现强制覆盖或接管入口 |
| 历史 | 过期引用、来源或会话切换、卸载后的旧卡 | 旧动作不自动转移，必要时重新查询 |
| 读取 | 加载、失败、部分失败 | 保持已知信息，未知不冒充空列表 |
| 布局 | 长名称、多条结果、窄屏、深浅主题 | 不截断范围与确认目标，按钮不拥挤 |

场景切换、故障注入和重置属于原型演示控制台，不是最终产品控件。模拟数据不表示真实安装、模型调用或宿主兼容验收；正式实现必须使用真实 Host 状态和组件，不复用模拟写入逻辑。


原型重点交叉场景：

1. 检查用户版期间切到项目版，迟到结果仍属于用户版，不能覆盖项目版状态；确认期间不切换原目标。
2. 用户版被项目同名技能覆盖，或技能禁止用户调用时，不能悄悄使用另一份；安装存在不等于可调用。
3. 用户位置可读、项目位置不可读时，项目状态保持未知，不展示成未安装或宣称只有一份。
4. 明确要求更新或卸载某位置时直接呈现该操作；默认展示位置不代表用户授权。
5. 卸载一份后另一份仍保留，原回执、失败重试和后续操作不能自动转移到剩余位置。


### 卡片尺寸与按钮取舍

少量内容不铺满对话区。常规单技能结果采用内容宽度约束，宽屏最大约 560–600px、内间距 10–12px；单份安装不额外占一行位置选择，双份安装保留紧凑位置选择和对应版本。小屏允许换行，不截断目标范围。高度是布局目标而非固定裁剪。

| 当前状态或用户意图 | 保留操作 | 不显示 |
| --- | --- | --- |
| 正常查询且可用 | 使用；更多内检查更新/卸载 | 常驻刷新、重复详情 |
| 已确认存在更新 | 更新；其他低频管理按需收起 | 多个同权重主按钮 |
| 已是最新 / 指定版本无需更新 | 必要版本结论 | 重复检查、更新 |
| 目标不明确 | 技能或位置选择、取消 | 未选择就执行 |
| 更新/卸载确认 | 取消、确认具体动作 | 使用、更多、切换目标 |
| 正在执行 | 状态；仅需要人工恢复时提供原操作查询 | 再次提交 |
| 成功或已取消 | 结果 | 刷新、重试、重复返回入口 |
| 读取失败 / 过期记录 | 重试读取或重新查询 | 直接执行旧动作 |
| 写入结果未知 | 查询原操作 | 重新执行、假定成功 |
| 本地修改 / 共享归属 / 外部来源 | 简短限制说明；仅明确安全可用的动作 | 强制覆盖、强制卸载或接管 |
| 文件缺失 | 清理记录并确认 | 使用、更新文件 |
| 空列表 / 读取中 | 空态或加载状态 | 无效操作 |
| 使用案例选择 | 选择案例、填入、取消 | 自动发送 |

恢复操作按真实错误原因呈现；不能把所有错误统一塞入“重试”。原型对这份按钮取舍进行场景检查，正式插件按此规则实现，完成情况以 verification.md 为准。

分组不改变安装目标身份：同范围存在多个位置时须保留可区分目标，不能仅以 scope 去重。切换位置只改变显示和后续操作选择；正在执行的请求及其结果仍绑定原 itemKey，确认期间锁定原目标。


## 多技能双列与连续对话验收

用户要求在真实 DSH 中展示：多技能结果按实际工具容器宽度排列为两列，小容器或窄屏降为一列；单技能保持紧凑宽度，不把两张 590px 卡并排。每个技能独立保留位置选择和操作目标，长名称允许换行，不截断范围与版本。更多菜单必须在底部或边缘可见、可点击。

按钮语义保持一致：使用技能只启动案例/草稿流程，不自动发送模型消息；检查更新只读；更新/卸载经真人确认才写入选定目标。按钮改变真实安装状态，不伪造或改写历史模型工具结果。后续模型对话对当前安装状态的回答应依据新查询，不把旧回执当现状；Host 对过期引用继续拒绝，不能自动重绑新目标。

本轮需在真实模型会话交替执行自然语言与按钮：查询多个技能 → 按钮更新一份 → 自然语言再问版本 → 旧卡片防护 → 对话卸载并取消 → 再问是否仍安装。记录模型是否重新查询、是否重复提交、操作是否正确隔离；模型回复缺陷和实际写入保护分开判断。测试技能可用隔离夹具，但模型历史必须真实产生。


### 连续对话状态同步

实测证明只要求模型重新查询不足以避免旧状态回答。采用两版支持宿主的官方异步 `system-prompt/assemble` 通道，使用可信会话与工作目录读取当前来源的本地安装投影，追加独立命名的运行时上下文。该段是插件提供的当前事实，不伪造用户意图或工具历史，也不触发额外模型调用。

上下文只包含技能身份、位置、版本、存在状态与完整性标记；不包含凭证、真实路径、来源 URL、内部调用引用或原始异常。读取失败、部分不可读与截断均明确说明，模型不得用未列出推断未安装。条数与字符数有上限，不请求远程市场；保留宿主其余上下文与工具。写入仍使用新查询取得的真实引用并经真人确认，运行时快照不是授权。

宿主明确抑制可选运行时上下文的模式应遵守官方语义，不绕过抑制。该模式下不能声称自动提供最新状态，仍须工具查询；实际兼容与降级限制需在验收结果中单独记录。

每轮重新读取，但相同公开状态生成稳定上下文文本，不加入每步变化时间戳以免破坏宿主去重。观察时间由官方运行时事件记录；状态变化才产生新的事实段。

更多操作展开不得把位置、版本和主要操作挤入菜单区域；展开项应有清晰独立布局，关闭恢复紧凑状态，首末卡片及窄容器均可触达。布局调整不改变原请求引用、重复点击锁及真人确认。


### 混合安装卡片对齐

正常卡片统一为身份、位置、版本与操作三行。单份位置文本与多份位置选择占据同等高度的行，不给单份安装绘制无效 Tab。正常短名称场景各卡等高、对应行对齐；长名称及窄屏可换行，不固定高度裁切。展开管理操作独立增加末行，不挤动原来的三行。多技能列表初始展示 6 个技能，每次追加 6 个，以匹配双列布局；未展示项通过“查看更多”进入，不改变安装记录数量或查询范围。


### 同名技能的使用限制

“使用此技能”必须核验所选安装是否为 DSH 当前会话实际发现的技能。另一份同名安装生效时，阻止草稿填入，不自动切换目标或删除任何安装。提示说明所选安装当前未生效，引导用户检查安装位置；响应未提供胜出位置时，不猜测用户级或项目级优先关系。使用错误展示在卡片独立全宽行，不挤压版本与操作按钮，也不因此禁用原本允许的检查更新或卸载。切换安装目标后清除上一目标的使用错误。
