# SkillHub DSH 原生插件发布说明

## 版本与交付状态

`@astron-team/skillhub-dsh@0.3.1` 已发布，独立标签为 `dsh-v0.3.1`。[发布准备 PR #995](https://github.com/iflytek/skillhub/pull/995) 已合并，[专用发布工作流](https://github.com/iflytek/skillhub/actions/runs/39556075587) 成功；[公开 npm 包](https://www.npmjs.com/package/@astron-team/skillhub-dsh/v/0.3.1) 与工作流产物逐字节一致，`latest` 指向 `0.3.1`。两版 Linux 的严格安装、原生探针及浏览器操作复验通过，测试工件与公开包字节一致，结果见 [验证摘要](verification.md)。历史已发布版本保持不变。

## 0.3.1 DSH 双 RC 兼容

- **精确发行版**：支持一致的 DSH `0.2.0-rc.2` 或 `0.2.1-rc.2` 依赖图；Host、app-boot、核心模块及注入 Client 模块必须同版，未知或混装继续拒绝新写入。
- **依赖与协议**：旧 RC 保留既有两组完整 Cordis 组合，新 RC 仅使用 `4.0.5 / 1.0.6 / 1.0.10 / 1.1.7`。构建生成器输出双方可读取的共同契约，运行时协议仍由目标 Host 提供，不使用 peer 豁免绕过兼容检查。
- **保留行为**：默认来源保持 `https://skill.xfyun.cn`，保留自定义来源、用户/项目范围、原安装记录和历史回执；不新增服务端接口、模型配置或登录功能。
- **验证范围**：功能候选完成 365 项测试、两版 Linux Host 严格安装、原生探针及浏览器用户/项目安装→升级→卸载和取消验证。CI 覆盖旧 RC 三平台双 Node、新 RC Linux 双 Node。新 RC 的 Windows/macOS 原生文件操作、真实桌面客户端及本次真实模型调用未验收；这些结果不代替 `0.3.1` 最终候选与公开包验证。

Node 保持 `>=24.2.0 <25`。精确兼容与验证边界见 [兼容设计](compatibility-design.md) 及 [验收标准](acceptance.md)。

## 0.3.0 市场交互与版本管理

- **卡片直接操作**：点击卡片进入详情，安装、卸载和检查升级使用独立按钮；仅存在当前来源安装时显示状态。内置标签中文展示，未识别标签保留来源名称。
- **详情与版本**：隐藏完整 Markdown frontmatter，改善正文排版；短期缓存避免返回详情时反复空白加载。版本接口支持可选 `downloadableOnly`，过滤后再分页并按发布新旧排序，默认管理历史查询保持不变。SaaS 新接口契约需单独同步。
- **范围选择**：项目范围只写当前可信工作区，用户范围供当前 DSH Host 的该用户多个项目读取；已有安装默认选中实际范围。对话省略范围时优先使用输入框旁原生问题，取消不写入，缺少问答服务则回退确认卡片。
- **安装和卸载**：确认后安装弹窗向右展开，仅展示阶段与结果；当前库存与历史回执分开。卸载从市场、列表和详情原地确认，精简非必要技术信息，保留原预检、幂等和恢复保护。
- **版本升级**：支持从已安装版本升级到选定的较新版本，也保留检查最新版入口。切换版本只读取信息，执行升级需要单独确认全部实际目标；同版不重复，旧版不降级，不可可靠排序时阻止升级，本地文件修改仍阻止覆盖。
- **默认来源**：保持 `https://skill.xfyun.cn`；自定义地址与显式空地址的断开行为保持不变。不要求单独安装 CLI，不读取 CLI 登录信息，不新增登录或权限功能。

候选完成构建、类型、Lint、357 项测试及 Linux 官方 DSH 浏览器生命周期验证，覆盖精确非最新版升级、最新版升级、取消、本地修改保护和真实文件核对。真实模型验证原生范围选择及项目安装，不代表技能内容执行。发布后公开包验证独立记录，不以候选结果替代。

## 0.2.1 默认正式来源

- 未提供 `registryUrl` 时默认连接 `https://skill.xfyun.cn`；显式空串或仅空白仍断开，已有自定义实例继续使用原地址。
- 默认值仅由 Host 配置 Schema 决定，不增加 Client 回退逻辑，不读取 CLI 配置或凭证；读取配置本身不发网络请求。
- 已发布的 npm `0.2.0` 已在隔离 DSH 中连接正式来源完成固定旧版本安装、文件和指纹核验、安装状态识别与 DSH 发现。`0.2.1` 候选和公开包验收单独记录，不以旧版结果替代。
- 日期格式等无法可靠排序的非 SemVer 版本继续按 `unknown-order` 阻断自动升级；固定版本首次安装通过不代表日期版本升级通过。本轮未调整版本比较或升级政策。
- 评论接口返回 404 时按可选能力缺失/未知处理，安全审核返回 401 时按匿名拒绝处理；不新增登录或开放权限。本轮不调用模型。

## 0.2.0 已发布能力

- **搜索展示安装状态**：技能中心卡片与对话搜索结果按 Registry 来源、命名空间和技能标识匹配受管理安装记录，展示已安装版本及当前用户/当前可信项目范围。不把其他项目或其他来源的同名技能当作当前来源安装。
- **异常与未知状态**：区分文件缺失、元数据异常和无法核验，避免把读取失败当成未安装。没有当前来源记录不代表 DSH 中不存在手工或其他来源安装，也不代表实际启用状态。
- **状态刷新与历史**：安装、升级、卸载后刷新当前页面；切换来源或会话时隔离缓存。对话保留查询时快照，历史卡片不会随之后的安装操作改写；重新搜索取得当前状态。
- **接口边界**：只复用本地库存及既有匿名 Registry 接口；不新增服务端安装状态 API，不改变登录、权限或审核策略。SaaS 适配事项见 [Agent 交接 Prompt](saas-agent-prompt.md)。

候选验收包含构建、类型检查、lint、295 项测试、12 项组件浏览器检查、9 项真实宿主页面检查，以及 `astron-code-latest` 的 3 轮对话、6 次模型请求。模型实际完成搜索、项目安装及安装后复查；市场数据为本地模拟，模型调用和文件安装为真实执行。详细范围见 [验证摘要](verification.md#7-搜索安装状态候选验收)。以上结果对应功能候选，不代替最终 `0.2.0` 发布包的完整性与安装验收。

历史版本 `0.1.1` 已发布并完成公开包完整性、干净安装及 15 项页面和重启验收；其发布标签的 Linux/macOS/Windows 原生 Host CI 六组通过。这些历史结果不代替 `0.2.0` 的最终发布验收。

- Host 重启后，历史安装回执核验原操作归属，再使用当前来源上下文读取安装记录和跳转已安装。会话、项目或来源变化时拒绝旧响应；不恢复过期搜索引用、安装目标或操作计划，不触发重复安装。
- CI 保留普通新装矩阵，并增加旧组合的独立 Host 回归。具体结果见 [验证摘要](verification.md)。

## 功能

- **原生技能中心**：侧栏使用专用 SVG 入口；浏览和已安装视图独立。紧凑头像卡支持首字回退、实际统计、分页、排序和来源提供的标签筛选。
- **详情与版本**：文档、版本、安全审核和评论按 `auto/show/hide` 展示；评论只读。可查看并安装指定的可下载版本，重新获取精确凭据，不绕过已有版本的冲突保护。
- **对话交互**：搜索结果使用紧凑卡片，详情抽屉沿用固定版本与来源校验。搜索本身不安装；用户明确要求安装时核验原搜索快照，未指定范围则先确认范围，再执行安装。
- **安装结果**：主区呈现简洁结果和查看已安装入口，展开安装记录可核验原操作与当前库存；历史完成、当前记录变化、发现状态和模型执行保持区分。
- **本地管理**：用户/可信项目安装、主动检查更新、完整目标集合升级、单位置卸载及失效记录清理。不存在自动更新、技能降级或强制覆盖。
- **配置与主题**：来源和详情标签使用 shadcn/Radix 组件；支持保存、重置修改、只读与 revision 冲突。“测试连接”读取当前草稿地址而不保存，显示公开目录或基础搜索可读性及耗时，10 秒超时可重试，改地址清除旧结果；不据此宣称下载和所有模块可用。界面跟随 DSH 深浅主题，提供窄屏布局、骨架加载及减少动画设置。
- **恢复与保护**：复用受保护的文件事务、inventory 和操作日志。响应丢失查询原请求，重启不自动重放未完成操作。升级、卸载与恢复仍核验来源、会话和目标归属。

插件内置共享安装核心，不要求另装 SkillHub CLI，不读取 CLI 登录凭证。浏览器使用宿主 React/React DOM；样式和交互组件限定于插件范围。

## 稳定性修复

- 安装受理后、写入开始前进程中断时，恢复可核实无写入状态并安全结束原请求，避免无效待处理操作持续阻止升级和卸载；未知或损坏日志仍拒绝自动处理。
- 已安装条目引用按范围和条目保持稳定；超过 400 条或重复刷新时，不再因缓存淘汰使刚展示的条目失效。实际操作仍重新核验可信上下文、记录和文件归属。
- 项目范围不可用时，正常用户范围仍可安装；当前选中范围存在不可核验记录时保留保护。
- 重复安装已存在的同版本后，以只读完整性核验确认 DSH 发现状态，不要求生成一次新的文件写入提交。

## 接口与配置

配置字段为 `registryUrl`、`detailTabs.versions`、`detailTabs.securityAudit`、`detailTabs.reviews`。地址禁止包含凭证、查询参数或片段；`0.2.1` 起缺省为 `https://skill.xfyun.cn`；显式空串或仅空白表示断开，自定义地址保留。配置页“已配置”仅指保存状态，不表示连通成功。

复用匿名目录、标签、搜索、resolve、元信息、固定版本说明/下载、版本及评论接口，没有新增服务端文件安装任务。安全审核保留匿名访问限制，不将无法读取显示为通过。SaaS 需同步实际路径、字段、公开策略和测试，不能用开源实例验收代替 SaaS 验收。详见 [Registry 契约](registry-api-contract.md) 和 [接口设计](interface-design.md)。

## 安装、更新与维护

可通过 `dsh plugin --profile skillhub-test add @astron-team/skillhub-dsh@0.3.1 --ignore-scripts` 安装到已有 Web Profile。发布前从源码执行 `bun run check` 后生成 `.tgz`，使用固定版本 DSH 的 `plugin ... add` 安装。具体准备、命令、配置和测试流程见 [中文指南](../../../plugins/dsh/README.md)、[英文指南](../../../plugins/dsh/README.en.md) 及 [发布指南](release-guide.md)。

更新或回退前保留原包和校验值、停止新操作并处理待恢复事务，然后停止 Host、安装兼容包并重新启动。浏览器旧资源可强制刷新；这不能代替 Host 依赖重载。禁用或移除包不会卸载技能，不应删除技能目录、inventory 或操作日志。

## 验证与限制

构建、类型检查、lint、单元/契约/打包测试均有对应检查入口；CI 包含三平台、两组 Node 版本和隔离 Web Profile Host 冒烟。实际结果须对应最终候选校验值，不以 CI 配置存在证明平台通过。浏览器验收覆盖配置、目录、详情、对话卡片、安装管理、主题、窄屏及加载/错误状态；人工 review 不替代自动化和文件事务验证。

明确限制：

1. 当前 UI 为中文，英文指南不代表英文 UI。
2. 真实模型行为取决于模型和会话；安装成功、DSH 发现和模型执行分别验证。资源路径成功个例不保证所有技能的相对路径解析。
3. 官方 RC.2 在同端口 Host 重启后可能使原标签页空白，不能承诺无缝重连；使用有效入口重新进入并查询原操作。
4. 历史验收覆盖正式 `0.1.0`→`0.1.1` 升级后原记录和技能保留、历史回执核验及导航，不承诺其他版本迁移或全部回退组合。未知格式不能通过删除日志绕过。
5. 注册、页面或工具共存测试不证明其他插件全部业务及模型选工具行为均兼容。

兼容范围以 [兼容设计](compatibility-design.md) 为准，行为门禁以 [验收标准](acceptance.md) 为准。

## 正式发布前门禁

- 确定正式版本、最终候选校验值和支持平台；未验证的平台、DSH 或 SaaS 组合不得声明支持。
- 验证候选包在干净目标 Profile 中安装、读取来源、安装测试技能及保留原数据的维护流程。
- 确认可发布 manifest、`dsh-v<version>` tag、npm 身份和发布凭证权限；配置了环境保护规则时完成相应审批；当前 manifest 显式允许公开发布，仍需完成最终候选验收及本次发布授权。
- 获批发布后，从 npm 下载实际包，对比完整性并执行发布后安装检查。

插件、开源服务和 SaaS 独立发布；npm 插件发布不部署服务端。
