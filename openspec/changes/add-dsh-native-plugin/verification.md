# 验证结果摘要

## 1. 当前结论

`@astron-team/skillhub-dsh@0.1.0` 已正式发布到 npm。发布后本地验收使用正式包、独立 DSH RC.2 Profile 和本地契约模拟市场；固定完整依赖基线时，14 项页面及安装管理用例通过，Host 重启后的历史卡片当前库存核验与导航失败。普通新装另复现了 Cordis 传递依赖漂移造成的写入禁用。实际文件、清单、会话、原操作及 DSH 发现保留正常，不能把卡片失败表述为数据丢失。

本分支修复上述两个问题，尚未发布新版本，不改变 npm `0.1.0` 的既有内容。修复后验收与 CI 结果在本文件单独记录；下表保留首版候选的历史验证范围。默认 Registry 仍为空，DSH 主基线仍为 `0.2.0-rc.2`，完整 Cordis 组合以 [兼容性设计](compatibility-design.md) 为准。本轮按用户决定不调用模型，也不代表真实 Java 服务端、SaaS 或其他操作系统已重新验收。

## 4. 关键人工问题的修正

| 反馈 | 修正 | 验证 |
| --- | --- | --- |
| 搜索后直接说“安装第二个”被拒绝 | 分离候选展示与Host安装核验，固定搜索版本并重查可信上下文 | 精确版本、歧义、取消与来源变化测试；官方工具零详情调用实际安装 |
| 安装回执过长 | 主区仅身份、版本范围、状态及一句结果；诊断记录默认折叠 | 历史无法核验仍显示提示，失败和未知仍保留核验入口 |
| 页面只有“正在读取来源” | 保留完整布局，使用主题骨架 | 浏览器延迟3秒后恢复；后台失败保留原卡片 |
| 插件配置无法编辑 | ConfigForm绑定真实Host entry ID | 构建产物契约测试与真实插件配置页读取 |
| 配置页缺少连接测试 | 草稿地址匿名只读探测，不保存来源；小号按钮 | 实际可用/不可达地址、总超时、取消、旧结果隔离和重置 |
| 早期中断安装长期待处理 | 执行租约与目标核验后安全结束未开始写入的请求，保留日志 | accepted/staging、有根/缺根、活跃执行拒绝及Host待处理计数归零 |
| 重复安装发现状态无法确认 | 保存原只读基线，观察前后核验版本、指纹、归属及清单 | 首次与幂等安装均能确认；内容变更、旧日志缺基线保持未确认 |
| 已安装引用被缓存淘汰、范围降级扩大 | 不透明摘要引用替代条目缓存，目标范围独立判断 | 401条逐项读取、重复与跨会话刷新、失效上下文及双向范围降级 |
| 旧页面空白、看不到记录 | 核对Host、认证与数据，重新进入并强制刷新 | 会话记录完整；用户明确确认刷新后恢复 |
