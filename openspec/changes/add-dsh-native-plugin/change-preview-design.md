# 升级变化预览与本地文件撤销

## 1. 范围与已确认交互

本设计承接已确认的顺序原型，补充正式实现契约，不表示代码或接口已交付。

1. 详情页按精确安装位置进行只读本地检查，发现修改时在对应安装管理位置显示轻量「本地修改 · N」查看入口，不占正文顶部提示行，也不要求先点击升级。日常「使用技能」以紧凑按钮放在右侧操作区，不在标题下独占一行。
2. 点击升级先重新检查本地状态。有修改时先进入「处理本地修改」；可逐文件／全部撤销，或选择「备份修改并继续」。这一阶段不展示发布版本差异。
3. 没有修改，或受确认的修改快照已经可靠备份后，进入独立「版本变化」预览。只展示原始旧发布内容到目标发布内容的变化、可用的作者更新说明。
4. 「确认升级」才授权技能替换；「备份修改并继续」只创建本地备份和后续计划，不修改技能或库存。取消版本预览不删除已经创建的备份。
5. 独立「查看本地修改」入口只负责查看／撤销，返回详情，不迫使用户进入升级。文件内容区桌面最大 320px、窄屏最大 240px，独立双向滚动、可键盘聚焦，文件头在滚动区外。

不提供两个比较对象并列的 Tab，不重复设置「升级」和「确认升级」主动作。不加入逐文件择版合并、版本降级、升级后版本回滚、自动升级或本地文件上传服务端。

## 2. 比较对象与可信基线

| 比较 | 左侧 | 右侧 |
| --- | --- | --- |
| 本地修改 | 当前安装版本的原始发布内容 | 当前实际安装文件 |
| 版本变化 | 当前安装版本的原始发布内容 | 用户选定的精确目标发布内容 |

基线绑定完整来源身份、namespace/slug、version/versionId、安装元数据中的发布指纹及目标路径；不可仅凭名称或版本字符串取得另一来源同名内容。

原始文件从现有精确版本 resolve 与归档下载链路取得，复用归档路径校验和指纹算法；归档计算指纹必须与已记录的发布指纹一致。元数据仅有哈希，不可用哈希伪造原始正文。缓存命中仍按该身份和指纹验证，不以当前源 latest 补齐旧基线。下架、权限拒绝、超时、指纹不一致分别保留明确失败，不报告为「没有修改」。

本地读取先核验可信安装归属、规范化路径、普通文件树及上下文。符号链接、路径重定向、未知归属、共享套件目标或不完整记录不能进入写操作；读取错误不是文件删除。只允许 Host 在既有权限内读取，不把任意绝对路径交给 Client。

启停入口按可信安装状态逻辑映射：停用安装的实际 `SKILL.md.disabled` 对应发布 `SKILL.md`；启停转换本身不是用户修改。撤销入口内容时保留当前启停状态，不恢复出第二个入口；存在冲突入口时拒绝。`.skillhub` 中安装元数据与内部状态不是可撤销的用户内容；作者的 `.skillhub/examples.json` 仍按发布内容比较。库存继续保持 v2，不迁移或新增旧消费者无法解析的库存字段。

## 3. 读取与展示上限

本地修改清单可直接比较可信元数据的原发布哈希与实际文件哈希，不要求预先下载原文；原文不可用仍可报告已检测到修改，但不能提供正文对比或撤销。Host 返回文件增删改清单和真实计数，正文按用户展开文件后按需读取；不一次把完整归档或本地文件树传到 Client。每个差异结果明确 `可展示文本 / 二进制 / 超出限制 / 不可读取`，二进制仅展示类型和可验证的大小变化。超过文本字节、行数或计算预算时返回截断／不可预览状态，不能显示为无变化。正文每侧最多256KiB，最多2000行，并使用有界计算预算，不能对任意大小输入运行无界二次方比较；实现以共享具名常量统一定义并测试，Client 不用截断后的内容进行写授权。

行内差异先展示必要上下文；长行在代码区域横向滚动，页面不横向溢出。没有作者更新说明时省略该块，不自动生成解释。刷新、失败重试和切换来源／会话／安装位置均保留明确语义，迟到结果不覆盖新上下文。

## 4. 撤销本地文件修改

撤销只针对当前安装版本，不改变安装版本、release identity、installedAt、归属或其他安装位置。

- 已修改发布文件：恢复该版本的原始字节。
- 本地新增文件：确认文案明确删除该新增文件。
- 本地删除的发布文件：恢复原始字节。
- 全部撤销：预检固定本次全部增删改路径，确认显示文件数量；不会把执行前新增的文件隐含加入。

预检生成绑定来源、会话、安装位置、当前版本、完整文件快照、选中文件集合与基线指纹的短期计划。确认执行时在既有目标锁和库存 CAS 纪律下重新核验，任何相关文件、元数据、路径、启停或归属变化均使计划失效；不得只看单文件 mtime。Client 不能提交任意正文或文件系统路径来替代 Host 已确认基线。

撤销执行扩展专用文件重置操作日志与恢复分支，复用既有目标锁、操作归属和事务纪律，先暂存全部变更再提交；不能把文件撤销伪装为 `installSkill`，因为其发布指纹与安装恢复假设不适用于局部文件重置。库存及安装元数据保持原发布基线不变，不能把当前本地修改登记为新的发布基线。全部撤销不能在中途错误时报告完整成功。中断或失败报告实际完成／恢复／待核验状态，重启不自动重放用户写意图。用户取消不写入。

## 5. 备份后确认覆盖升级

这是对旧「local-changes 一律阻止」的受限扩展，不是公开 force 开关。旧升级调用与未携带已确认快照的路径继续拒绝本地漂移。

### 时间与授权

1. 「备份修改并继续」在锁内取得所选安装的完整当前文件快照，核验原始基线及目标身份，创建并验证持久备份；技能目录和库存保持不变。
2. 返回不透明备份／预览引用，绑定精确安装、快照哈希、原始发布与候选发布身份、来源和会话。该引用不是执行升级的用户确认。
3. 展示发布版本变化；只有用户点击「确认升级」才生成／执行对应升级确认计划。
4. 提交前再次在目标锁下核验该本地快照、库存、启停、归属、权限、目标发布指纹与备份完整性。任一变化均拒绝并回到处理步骤，不复用旧授权或悄悄扩大覆盖范围。

只对已明确确认、完整备份的同一快照执行覆盖。复用 `expectedTargetFiles` 传递用户确认的完整实际文件快照，并保持 `allowTargetDrift:false` 执行锁内比较；修改快照是本次授权的执行前状态，不是库存或安装元数据的新发布基线。不得全局修改 `allowTargetDrift` 默认值或绕过原始来源冲突、共享目标、未知版本顺序及相同版本内容漂移保护。旧 CLI 正常语义不变。

### 备份与缓存分离

备份位于由可信 `stateDirectory` 推导的同级 `backups` 目录（`dirname(stateDirectory)/backups`），与技能目录和发布缓存分离，以 Host 生成的 UUID 标识；目录名不可由 Client 指定，不能被技能发现机制加载。备份包含完整实际内容、必要启停映射及来源／版本／文件哈希清单，不存凭证；发布基线缓存另存，不冒充用户修改备份。

备份写入临时目录，逐文件校验后原子提交清单；成功回执之前必须证明内容和清单一致。权限拒绝、磁盘不足、复制中断或最终校验失败均停留在处理页，不进入版本预览、不覆盖文件。失败的半成品不当成成功备份。

单份备份上限100MiB，与既有包下载上限一致；单Host持久备份总量上限1GiB、最多20份，任一达到上限则拒绝新增备份。创建前与最终提交均在备份存储锁下复核限额，防止并发突破总量；沿用归档单文件／路径等适用限制并统一具名常量。持久备份不在升级成功、取消预览、缓存淘汰或插件重启时自动删除。第一期不设置自动过期清理、不提供版本回滚；容量不足时明确拒绝新备份，不能以删除既有用户备份腾空间。界面给出可定位的备份记录或路径用于用户保留，不把备份称为已有回滚能力。显式备份清理入口不属于本期。

原始发布缓存可以按完整性校验后的独立缓存策略淘汰；淘汰后需重新取得基线，不能退化成不核验写入。

## 6. 层次与接口边界

- Registry：复用已有精确版本解析、文件／ZIP 下载和更新说明，不增加安装、diff 或本地文件上传公共 HTTP API。
- 共享本地核心：持有原始内容校验、实际文件快照、差异清单、撤销事务、持久备份与受确认快照的升级执行。
- DSH Host 私有 Remote：提供按安装引用的只读清单、按文件受限正文差异、撤销预检与确认执行、备份继续和升级预览能力；保留 Agent-scoped 权限、sourceRevision／itemKey 和不透明计划引用。方法名及生成类型由实现契约统一产生，不在 Client 另造第二套文件操作。
- Client：顺序视图、懒加载差异、明确确认和状态展示，不持有任意路径写能力，不将只读检查结果当执行授权。

其他来源安装可按原有可信来源获取当前版本基线并进行本地查看／撤销；更新预览和升级仅允许当前来源。切换来源后尚未受理的升级流程失效；已受理事务仍以固定来源完成或恢复，不能路由到新来源。SaaS 支持状态必须单独联验，不因开源源码有接口即宣称现网支持。

## 7. 验收矩阵

1. 详情提前提示本地修改；只查看可直接返回；升级顺序符合 §1，无双 Tab 混淆。
2. 精确版本的增／删／改、空文件、Unicode、长路径、二进制、超长文本、异常编码与截断状态。
3. 无基线、下载拒绝、指纹错、读取失败和离线缓存命中；所有未知均不假报无修改。
4. 单文件撤销、全部撤销及取消，新增删除确认明确，版本／归属／未选目标不变。
5. 启用和停用安装撤销后状态不变，入口冲突、元数据与共享归属不能误写。
6. 预检后文件变化、文件替换链接、并发 CLI、库存变化、切源和上下文变化使旧计划失效。
7. 备份成功后取消不写技能且保留备份；备份失败不进入预览；确认升级前新修改要求重新处理。
8. 正常无修改升级与旧 CLI 回归；备份授权不影响旧路径的漂移保护，库存保持 v2。
9. 撤销和备份覆盖事务的代表性中断、恢复及重复请求；不能把进程内错误模拟当作全部平台进程强杀验收。
10. 真实 DSH 1440／390、明暗主题、键盘焦点、每文件独立限高滚动；本地修改不上传服务器。

## 8. 新旧消费者日志兼容

库存 v2 兼容不代表操作日志兼容。新增文件重置日志放在独立的新操作子目录，不把新kind或schema塞进旧OperationStore会当作损坏记录处理的既有目录。新Host启动时读取并识别新旧两类待恢复操作；任一未核验的pending新事务均阻止本Host的新写入，不得仅因旧listPending为空就开放安装、升级、卸载或启停。恢复只接受同一精确目标与有证明的before/after快照。

旧CLI仍通过现有目标锁／库存锁参与互斥，不能更换成仅新Host可见的另一套目标锁。旧DSH不承担新文件重置日志自动恢复，但不得把它作为损坏旧日志无声清除。向旧插件回退存在新pending日志时，不宣称兼容恢复完成；须先用支持该事务的版本完成核验。测试单独覆盖旧库存读取、新日志隔离与pending阻写，不以拒写替代正常旧CLI查询／管理兼容。

正式支持平台和真实模型／宿主验收分别记录，编译与原型截图不替代生产功能验收。

## 9. 文件事务与失效诊断补强

新文件撤销补实际子进程终止矩阵，覆盖写入意图、旧目录已移动、新目录已发布、持久提交后清理前及清理途中；每组重启后通过实际目录内容、原始元数据/库存、入口启停及日志证明最终状态。未能证明的现场保持 recovery-required，不把外部新增内容当作可删除事务遗留。测试应区分真正进程结束与进程内异常模拟，平台结果分别记录。

普通安装的 CONTEXT_STALE 保持原来的拒绝语义；安全诊断通过固定枚举说明哪个上下文约束失效，不序列化实际路径、凭证、内部对象或任意异常正文。日志足以支持复现和定位，但不把“同SHA重跑未复现”当作根因已解决。对观察到的初始化时序，只能在保留权限/来源/会话约束并有回归证明时最小修复。

本轮补强实现：已提交清理恢复先证明目标为after、staging不存在，剩余备份只可为可信before文件/原目录子集；哈希前执行资源预算，授权等待后重新核验目标和剩余备份。新增目录清单为独立撤销日志可选字段，旧记录保持保守验证，不迁移库存。任意未知文件、目录、链接、篡改或过量内容均拒绝清理。普通安装诊断采用固定内部原因枚举，不新增Remote端点或模型结果字段，旧静态错误文案保持。
