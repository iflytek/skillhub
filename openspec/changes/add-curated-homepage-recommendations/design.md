# 技术设计

## V17 系统配置整合

沿用同一配置页和四分区，不新增管理入口。站点信息保留直接保存即生效；推荐仍独立保存草稿、预览、发布。站点配置新增 `sections.curated.enabled`，复用现有 JSONB、版本与审计，不新增表。缺少该键的存量配置按默认启用归一化，显式关闭保留；关闭只控制首页模块，不改变推荐的配置数据或只读专题路由。

站点编辑采用单主内容区及名称标识/首页内容胶囊。首页预览为宽版只读弹窗，复用真实页面展示与公开数据，通过受控配置覆盖当前编辑值；不保存、不污染公共查询缓存，不把示例技能或客户端示例角色写入真实产品。品牌资产仍遵循既有上传即公开的语义。

登录、头像、邮件分别保存，首次外部授权规则按条操作。通知维护的三个局部面板共用胶囊导航；SMTP就绪仅代表配置存在，不能展示为连通/送达保证；索引重建按实际同步接口反馈，不能虚构任务进度。分区离开保护由父级协调各面板的dirty/busy状态，取消不丢输入；错误和409沿各接口实际契约处理。

## 持久化与发布

推荐使用单独的 `system_setting` 键 `site.recommendations`，与立即生效的 `site.presentation` 隔离。复用 JSONB 与 JPA `@Version`；草稿保存和发布均在事务内比较客户端版本，冲突返回409且不覆盖新值。保存仅更新 draft，发布复制已保存且重新校验的 draft 到 published 并记录发布者/时间；公开端点绝不读取 draft。

未形成显式发布快照时可使用平台初始策划；仅解析 builtin publisher 所有、实际可用的 @global 预设技能。显式发布空数组是有效覆盖，不恢复初始策划。读取默认值不写数据库，不因异步初始化失败宣称已安装。普通 RECOMMENDED 标签不决定是否精选。

## 约定的数据结构（本次新增）

- `RecommendationContent`：`topics` 有序数组、`featuredSkillIds` 有序技能 ID 数组。
- `RecommendationTopic`：稳定字符串 `id`、`title`（1–80）、`description`（0–300）、站内可选 `coverUrl`、`enabled`、有序 `skillIds`。
- 上限：12个专题，24个首页精选，每个专题24个技能；同集合不允许重复 ID。专题 ID 不由数组索引派生。草稿可保留不可用引用供修复，但发布须校验可展示内容。
- 管理响应包含 `version`、`draft`、`published`、可公开展示的 `skills` 批量摘要、发布元信息及是否使用默认策划的信息。引用与摘要分离，避免把客户端提供的标题/权限当成服务端事实。
- 公开首页响应仅返回 enabled 且至少存在一个当前可用技能的专题摘要（包含最多3个预览技能）、有序精选；专题详情单独返回其当前可用完整技能列表。

## 新增接口契约

- GET/PUT `/api/v1/admin/system-config/recommendations`：读管理快照／保存草稿；PUT 包含 `version` 和 `draft`。
- POST `/api/v1/admin/system-config/recommendations/publish`：请求 `version`，仅发布服务端已保存草稿。
- GET `/api/v1/admin/system-config/recommendations/candidates`：分页查找当前公开可推荐技能，支持 `q`、`page`、`size`，不使用管理员宽权限替代公开资格。
- POST 复用 `/api/v1/admin/system-config/presentation/assets` 上传专题封面，沿用2MiB PNG/JPEG归一化及站内 UUID 引用验证。已上传资产沿用现有公开资产语义；草稿的配置数据保持私有。
- GET `/api/v1/site-recommendations`、GET `/api/v1/site-recommendations/topics/{topicId}`：匿名只读已发布投影；未发布/禁用/空专题返回404。

接口使用现有 ApiResponse、分页、身份/CSRF、异常和审计规则；公开路径同步路由安全策略。DTO及精确分页形态由现有类型映射，不新增第二套 envelope。

## 资格与读取

公开投影和管理候选必须独立于查看者角色：当前 PUBLIC、ACTIVE、非 hidden、空间非归档、有效且可下载的 PUBLISHED/latest 版本，排除撤回。复用生命周期已发布展示摘要、SkillAvatar、namespace和标签批量映射。保存草稿不泄露到公共缓存；发布后失效公开推荐查询。后续可见性/归档/治理变化在每次公开读重新过滤，不回传失效项的标识或元信息。

## 前端

- 复用 TanStack Query/API client/Radix Dialog/现有 SkillCard 与 SkillAvatar。新增 feature 保持 FSD，正式 DTO引用生成 schema。
- 系统配置分为站点与首页、精选与专题、账号与审核、通知与维护。旧表单功能、权限、失败/冲突和离开保护不删减。
- 默认草稿预览：专题桌面3张一组，窄屏单张浏览；真实精选卡片；查看专题进入只读页面，配置通过单个事务弹窗。
- 弹窗 working copy、返回视图、选择器、取消/Esc、应用行为与 V12 一致；发布需要单独确认。不把所有旧配置改成草稿。
- 拖拽采用经核实适合 React 的成熟库，稳定ID、仅手柄起拖、键盘排序、屏幕阅读播报及取消恢复；不复制离线原型的全局JS，也不添加运行时CDN。
- 经用户确认的原型是页面布局、内容层次、色彩分配与交互的验收依据；基础控件复用仓库设计系统及真实 React API。需要任务变体时明确记录并同步原型，不能在实现时自行替换已确认的头像、封面或布局。

## 备选

只给已有标签加首页展示无法提供平台独立策划及专题组合，且普通作者可管理 RECOMMENDED 标签，不能作为权限来源。新增独立配置数据库和专题关联表对当前有界集合没有必要。单行 JSONB 可原子管理快照与顺序，并复用既有并发控制；当未来策划规模突破当前上限再讨论实体拆分。

## V13 视觉修订（原型待确认）

本次用户反馈表明 V12 实现的弹窗空间、专题封面及头像表现未满足预期。保持既有数据和发布流程，先重新确认原型，再实施大范围布局调整。

- 专题管理和技能选择采用约1040px的任务工作区，专题编辑将字段与实时预览分区；宽度受视口限制，正文独立滚动，操作区可达。普通确认弹窗仍保持480px，不全局放大 Dialog。
- 专题封面使用原创任务图解与深绿、淡紫、浅蓝、暖杏、青绿等内容色；常规按钮、字段和正文卡片继续使用现有中性主题。内容色不被误作新品牌主色。
- 推荐和技能市场复用同一个业务头像：真实图片优先，否则首字母／首个中文字符；按照技能坐标稳定映射到八种浅色身份色，暗色配套，刷新不会随机换色。不再用固定线性业务图标覆盖头像。
- 单项启停用统一 Switch 及明确状态；待保存配置说明生效时机。多选仍保留复选语义，采用统一绘制的勾选样式，替换浏览器默认外观。
- 原型覆盖推荐专区、后台管理／专题编辑、技能市场及通知开关，验证桌面／窄屏、明暗、取消／应用、键盘与拖拽。


### V14 页面外壳核对

- 推荐原型使用 `web/src/app/layout.tsx` 的六项全局导航及真实路由。正常页面不展示模拟失败、模拟冲突或调试状态切换按钮；错误反馈仅在真实操作结果或验收脚本模拟时出现。
- `/admin/system-config` 按 `layout-main-content.ts` 使用普通页面外壳，不引入控制台 `DashboardSidebar`，也不高亮“控制台”或“治理中心”。系统配置入口依据 `user-menu.tsx` 的管理员菜单。
- 系统配置内侧导航依据 `pages/admin/system-config.tsx` 的四分区：站点与首页、精选与专题、登录与审核、通知与维护。平台业务邮件开关属于通知与维护，不冒充个人通知设置。
- 原型验收追加系统配置普通页面，检查完整顶部、内侧导航、选中态和操作区，不能仅核对裁剪后的弹窗。


### V15 实现边界
用户已确认按修正原型落地。复用当前真实React页面、API、四分区、身份与导航；不复制HTML演示外壳。封面可选六种内容风格通过可空coverStyle存入现有JSONB，缺省按专题id稳定选择；不新增SQL迁移或分类体系。候选筛选复用已有label slug，列表与总数必须同条件。宽任务弹窗为局部1040px变体，确认弹窗保持480px。草稿Switch为已确认例外，附近说明应用/保存后生效。对关闭菜单的Figma采集问题无需在产品复制采集代码；真实菜单复用既有组件并验证退出、互斥和焦点。

用户补充确认：封面仅结构和配色预设，业务文字读取实际专题title和关联技能displayName，改名、增删技能与排序时实时更新；没有业务数据的风格缩略图保留几何图形，不臆造交付文档或行动项。


## V21 专题窗口与 B 方案卡片（历史实现，展开方式由 V22 取代）

已确认的 V21 HTML 原型是本轮视觉/交互基线。公共首页和精选列表的“浏览专题”在当前页面展开专题集合窗口，不重排首页发现区。保留 `/topics/{id}` 直接访问兼容和技能现有详情路由；后台已有编辑回调继续使用工作副本，不因公开窗口改读已发布内容。

首页的专题摘要仅含最多3个预览成员，公共窗口必须通过现有专题查询取得当前可公开展示的完整成员；请求失败、404、空成员及加载中分别反馈，允许重试/关闭。查询使用 TanStack Query，不引入新接口、配置或权限。窗口只呈现本专题真实技能，使用说明按需加载现有文档能力，不自动执行技能或安装。

B方案卡片作为推荐域局部变体，不改变技能市场卡片结构。真实头像优先、回退首字母与稳定浅色，四语言和明暗延续项目组件/设计契约。

自定义封面在缩略图和窗口中完整按原比例显示，宽高由真实图片与容器共同约束，小图不超过自然尺寸。标题、简介独立于图片。失败显示替代状态，不妨碍成员浏览；不导入原型的图片演示选择器、假素材或本地上传入口。后台继续使用现有真实封面上传流程和限制。

窗口从来源卡片矩形进行外壳几何展开；非等比阶段不显示真实图片/文字，落定后淡入内容。关闭反向归位；旧动画回调不得覆盖新操作。使用现有可访问弹层基础，保持窗口内焦点、Escape/遮罩关闭、归还触发器焦点和页面位置；减少动态直接落位。手机窗口限制在视口内、正文内部滚动、关闭操作可达。已有页面预览中的嵌套弹层需保留父层语义和当前草稿。


V21 实施补充（用户确认背景规则）：自定义图片不负责提供窗口底色。预设与上传封面均复用该专题已选择的六种 `coverStyle` 内容配色；自定义图片舞台及标题区采用同风格浅色底，暗色采用对应语义底色。未选择风格时按既有专题标识稳定回退。保留现有风格选择，不新增颜色字段、不从图片自动提取颜色，不将全部自定义封面固定为绿色或灰色。


## V22 原专题区域展开与返回恢复

用户明确红框指原有专题推荐区域：浏览专题后，原区域的轮播被该专题内容替换，以封面/简介/收起入口和技能集合构成页内展开态；下方发现/筛选区保持独立。不使用弹窗、遮罩、焦点锁定或页面滚动锁定，不在发现区下面再附加详情工作区。展开/收起在同一区域适度过渡；减少动态直接落位。

删除专题集合中的“使用说明”入口及文档查询/Markdown阅读区，只保留现有技能详情链接。浏览器从详情返回时，恢复该首页或精选列表历史条目的展开专题、搜索、标签、轮播位置与页面滚动；不同历史条目不互相覆盖。不改变全局路由滚动策略，仅保存本功能的纯公开UI状态，不缓存技能响应或管理员草稿；专题和技能资格继续按现有接口读取，已失效项不能靠历史快照复活。

后台策划预览使用同样页内展开，但仍只消费本次草稿快照，不向公开查询泄露编辑数据；站点首页宽版预览保持既有只读限制。自定义封面、六种底色/暗色、小图原尺寸和推荐域B卡沿用已确认规则。V22仅改变展开位置、移除阅读区及返回体验，不引入接口/数据库/权限变化。


V22返回实现选择：使用已安装路由实际生成的 `__TSR_key` 与当前 href 标识历史条目，最多保留20条纯公开UI快照于当前标签页 sessionStorage。不调用 history.replace（该实现会重新生成entrykey），不启用全局scrollRestoration。详情导航前同步保存原条目；恢复仅在当前完整专题和布局就绪后执行，不播放首次展开动画、不重复夺取滚动。存储不可用/无效时退回正常可用界面。草稿和只读首页预览均禁用持久恢复。


## V23 页内展开高度边界

展开专题整个容器采用视口相关最大高度，避免技能集合撑长首页。返回专题列表操作始终可达；封面与技能集合在同一个内部滚动区域中，页面仍正常滚动，不锁body、不增加遮罩或弹窗。短内容按实际需要占高，不用空白填满；窄屏和较矮视口同样限制在可操作范围。

详情返回恢复扩展为当前条目的区域内部scrollTop与页面windowY；新增纯UI字段缺省按0读取，兼容V22已保存状态。内部滚动与导航前均记录最新位置，仅公共页面有效；仍遵循完整数据就绪、离场取消迟到恢复以及草稿/只读预览禁存储的边界。
