# 文档治理与归档规则

## 目标

当前仓库文档已经覆盖架构、协议、需求、实现、历史计划、专题分析、对外站点等多个层次。  
问题不在“文档不够”，而在“入口过多、历史与当前混杂、归档边界不够明确”。

本文件定义当前建议的文档收敛规则。

## 当前推荐结构

### `docs/`

只保留仍然适合作为“当前入口”的文档：

- 产品方向、系统架构、领域模型、认证设计、搜索架构、业务流、API 设计
- 部署、工作流、E2E、集成指南
- 文档站 `docs/skillhub`
- `docs/prds` 中仍未完成的需求文档

### `design/`

只保留“对当前代码仍有解释价值”的设计材料：

- 项目级分析
- 设计决策
- 外部依赖与兼容性分析
- 已实现需求归档

### `design/implemented/`

放“已经完成实现”的 PRD 与补充材料：

- 已实现需求不再放在 `docs/prds`
- 保留其原始需求背景，但角色转为“设计归档/实现回溯”

## 归档判断规则

满足以下任一条件时，应优先归档而不是继续留在主 `docs/`：

1. 文档描述的是一次性阶段计划，而不是当前系统入口
2. 文档描述的需求已经完整实现
3. 文档主要价值是历史追溯，而不是指导当前开发
4. 文档中的路径/流程已经明显过时

## 删除判断规则

满足以下条件时，可以考虑删除而不是归档：

1. 与其他文档高度重复，且没有补充信息
2. 引用全部失效，且内容也没有历史追溯价值
3. 内容只是中间产物、草稿、机械导出，后续从未使用

当前仓库已经做过一轮历史材料清理。对于明显无持续维护价值、且只会增加噪音的历史文档，允许直接删除。

## 当前建议保留在主文档区的内容

- `docs/00` 到 `docs/14` 一类核心系统说明
- `docs/19-smtp-password-reset-email-setup.md`
- `docs/dev-workflow.md`
- `docs/e2e.md`
- `docs/openclaw-integration*.md`
- `docs/security-scanning.md`
- `docs/skillhub/`
- `docs/prds/README.md`

## 当前建议归档的内容

已收敛或建议继续收敛的类型：

- 已实现 PRD
- 项目总览与实现归档文档

## 当前发现的问题

### 1. 绝对路径引用

部分文档仍包含开发机绝对路径链接，不适合仓库内长期维护。

### 2. 失效引用

少数 PRD/设计文档仍保留对不存在文件的引用，需要清理。

### 3. 仍需持续抑制文档扩散

即使已经做过清理，如果后续继续把阶段性分析、临时方案和实现草稿直接放入主 `docs/`，很快还会再次膨胀。

## 后续建议

1. 在 `docs/` 增加一份总索引 README
2. 统一把绝对路径链接改成相对路径或明确归档说明
3. 新增文档时，先判断它属于：
   - 当前入口文档
   - 已实现需求归档
   - 历史归档
4. 对数据库、运行模式、认证接入这类高频主题，优先维护“总览文档”，减少散点专题继续扩张
