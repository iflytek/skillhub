## Codebase Patterns
- 当 `skillhub.search.engine` 新增方言值时，`SearchQueryService`、`SearchIndexService`、`SearchRebuildService` 三类 bean 需要一起覆盖该条件装配；只补 query provider 会让常规事件监听和同步服务在启动期注入失败。
- MySQL 过渡期扩展 `migration-mysql` 时，除了请求主链路直接写入的表，还要同步覆盖发布后异步通知和删除清理会访问的表；否则 `local-mysql` 真实 smoke 可能在 `publish`/`delete` 后半段才暴露缺表。
- mysql-like 排序 story 可以直接与 h2-like provider 对齐：`downloads`/`rating`/`newest` 走 JPQL 属性排序，`relevance` 只在存在关键词时启用 `CASE + titleExact/titlePrefix/titleLike`，并且 count query 必须禁绑 relevance-only 参数。
- 本地运行态 smoke 最好在 `LocalDevDataInitializer` 里种一个确定性的可搜索 fixture，这样 `/search` 验证不需要依赖异步索引或额外的手工数据准备。
- Playwright 本地 smoke 如果要复用已启动的前后端，`PLAYWRIGHT_WEB_PORT` 和 `SKILLHUB_API_PROXY_TARGET` 都应可配置；这样同一条用例可以在手工浏览器和自动化跑法之间切换。
- mysql-like 搜索 provider 逐步补行为时，关键词 story 可以直接复用 h2-like 的 `normalizeKeyword + LIKE` 结构，只绑定 `titleLike` 这类当前 SQL 真正使用到的参数，避免 count query 因残留排序参数而失配。
- 迁移中的新搜索 provider 如果要按 story 逐步补行为，优先先让 SQL/JPQL 只覆盖当前 story 的过滤边界，并把关键词、排序、分页留在后续 story；这样可以复用现有 provider 契约而不把多个 acceptance criteria 混在一次提交里。
- 对于存 JSON 文本但领域层以 `String` 处理的字段，不要在 Hibernate 上继续使用 `@JdbcTypeCode(SqlTypes.JSON)`；它会把整段 JSON 当作字符串再次编码，`String` 字段应直接按普通文本列持久化。
- 为 MySQL 过渡期补真实持久化验证时，优先用 Testcontainers 拉起受控 MySQL，并让测试走 `migration-mysql` + `ddl-auto=none`；如果直接让 Hibernate 在全量实体上 `create-drop`，仓库里尚未迁完的 PostgreSQL 专属映射会污染验证结果。
- MySQL 过渡期如果扩展了运行时实体映射，记得同步更新 `server/skillhub-app/src/main/resources/sql/migration-mysql/V1__init_local_mysql_schema.sql` 和 `LocalMysqlSchemaMigrationTest`，否则空库启动路径会和 H2 测试路径漂移。
- 新增 Spring slice/integration 测试如果依赖仓库现成的 `application-test.yml`，要显式加 `@ActiveProfiles("test")`；`@DataJpaTest` 这类测试如果还需要保留该 profile 的 H2 datasource 初始化参数，再加 `@AutoConfigureTestDatabase(replace = NONE)`。
- Backend runtime database driver and Flyway database support are both wired in `server/skillhub-app/pom.xml`; switching the main relational runtime starts there.
- Flyway core and database-specific support module versions must stay aligned in the parent Maven dependency graph; mixing Spring Boot managed `flyway-core` with a manually pinned newer plugin can compile but will fail at runtime during migration bootstrap.
- This repo currently lacks the root `Makefile` referenced by `AGENTS.md`, so branch work may need to fall back to direct `mvn -f server/pom.xml ...` and `pnpm` commands for verification.
- Local runtime profiles that should boot without Redis must explicitly exclude Spring Session and Redis auto-configuration, then set rate limit, auth throttle, and UASS cache to in-memory/local modes in the profile YAML.
- Search runtime selection is currently driven by `skillhub.search.engine`; any non-PostgreSQL local profile must override the base `postgres` default or Spring will still wire the PostgreSQL search bean through `matchIfMissing = true`.
- When one runtime needs a different SQL dialect, give it a separate Flyway migration directory and validate version continuity per directory rather than enforcing one global version sequence.
- Local bootstrap on an empty database depends on `ApplicationRunner` ordering; if one runner requires seeded roles or the global namespace, make the order explicit with `@Order`.
- 迁移 PostgreSQL `ON CONFLICT` 写路径时，优先把 Spring Data interface 保持为基础 CRUD/定向 `UPDATE`，再用 `@Primary` adapter 组合成 `UPDATE -> conditional INSERT -> retry UPDATE` 的方言中立 upsert，避免把数据库特定语法塞进 repository 注解。
- 如果一个搜索 provider 只在特定方言下合法，查询、索引写入和 rebuild 三类 bean 都必须一起受同一 `@ConditionalOnProperty` 开关约束；只隔离 query bean 不足以阻止非目标 runtime 误装配 PostgreSQL-only 组件。
- 迁移中的新搜索 provider 可以先用“独立 package + `@ConditionalOnProperty` + 最小装配测试”建立方言边界；如果后续行为 story 尚未落地，先不要抢跑接入索引/rebuild provider，以免跨 story 扩大改动面。
- `local-mysql` profile 这类运行时切换，最好在 profile YAML 和配置绑定测试里同时显式断言搜索 provider 值；这样可以把“本地运行时”和“测试数据库”分层切开，避免 profile 仍回落到 `h2-like` 的默认路径。
