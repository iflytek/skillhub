## Codebase Patterns
- Backend runtime database driver and Flyway database support are both wired in `server/skillhub-app/pom.xml`; switching the main relational runtime starts there.
- Flyway core and database-specific support module versions must stay aligned in the parent Maven dependency graph; mixing Spring Boot managed `flyway-core` with a manually pinned newer plugin can compile but will fail at runtime during migration bootstrap.
- This repo currently lacks the root `Makefile` referenced by `AGENTS.md`, so branch work may need to fall back to direct `mvn -f server/pom.xml ...` and `pnpm` commands for verification.
- Local runtime profiles that should boot without Redis must explicitly exclude Spring Session and Redis auto-configuration, then set rate limit, auth throttle, and UASS cache to in-memory/local modes in the profile YAML.
- Search runtime selection is currently driven by `skillhub.search.engine`; any non-PostgreSQL local profile must override the base `postgres` default or Spring will still wire the PostgreSQL search bean through `matchIfMissing = true`.
- When one runtime needs a different SQL dialect, give it a separate Flyway migration directory and validate version continuity per directory rather than enforcing one global version sequence.
- Local bootstrap on an empty database depends on `ApplicationRunner` ordering; if one runner requires seeded roles or the global namespace, make the order explicit with `@Order`.
