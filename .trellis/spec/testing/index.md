# 测试与质量入口

正文读取与换会话接续遵循[有界读取规则](../workflow/context-reading.md)，按本页触发条件选资料，不批量加载整个目录。

实现后验证、测试设计、CI 或交付验收时读取。本目录说明怎样选测与执行；领域
quality-guidelines 说明必须验证的行为，业务预期来自正式设计、接口和验收标准。

## 按影响选择检查

先运行最小相关检查获得反馈，再执行本次影响范围的交付检查。跨领域修改取并集。
表中命令从仓库根目录运行；具体测试过滤参数按当前工具和相邻用例核对，不猜测。

| 改动与风险 | 检查入口 | 应留下的可观察证据 |
|---|---|---|
| 工程规范与索引 | `python3 scripts/check-engineering-specs.py`；检查命令来源、规则冲突 | 链接目标、迁移去向、检查范围；不是规则加载成功的证明 |
| 仅修改既有翻译资源的显示文案 | 检查资源语法、键/插值一致性与相关界面；影响布局时检查长文本和小屏 | 显示语义与资源消费正确；规范校验器不能替代文案验证 |
| 仅 CLI 帮助显示字符串或说明文档 | 源码帮助字符串执行相关帮助输出测试，确认用法与退出语义；仅文档检查链接和命令来源 | 实际帮助输出或文档引用；不追加无关前后端构建 |
| 前端状态、组件、请求 | `make typecheck-web`、`make lint-web`、`make test-frontend`；交付补 `make build-frontend` | 受影响行为与错误分支通过；可见改动另做浏览器验收 |
| 后端应用与领域规则 | `make test-backend-app` | 当前源码及依赖模块测试结果，包含适用拒绝/失败分支 |
| 共享后端模块、构建依赖、广泛契约 | `make test-backend` | 受影响消费方和全模块结果 |
| SQL、事务、并发、迁移 | 后端检查加[数据库与并发测试](./backend-testing.md) | 在真实依赖上观察提交、回滚、竞争与迁移；mock 不替代 |
| API 契约或生成类型 | `make generate-api`，按需 `./scripts/check-openapi-generated.sh`；前端类型与消费方检查 | schema 差异已审查；响应与错误语义有断言 |
| 身份、权限、操作流程 | 后端边界测试 + [真实 E2E / Smoke](./e2e.md) | 允许与拒绝、跨账号/命名空间隔离、最终持久状态 |
| CLI | `make lint-cli`、`make typecheck-cli`、`make test-cli`、`make build-cli` | 退出码、输出、状态文件和子进程行为；见[CLI](../cli/index.md) |
| 配置、容器与发布路径 | `make validate-release-config` + 受影响构建/Smoke | 配置生效与业务路径分开证明；见[部署](../deployment/index.md) |
| CI 与检查脚本 | [CI 规范](./ci.md) + 代表性通过/失败/跳过输入 | 能检出错误，失败正确传递，没有误报通过 |

上述文案例外仅适用于不改变键、插值参数、分支、事件、样式、参数解析或生成逻辑的显示文本。
一旦涉及这些行为或工具链，升级到对应领域检查；跨域取并集，不仅凭文件扩展名决定范围。
文档站内容另核实际构建/CI要求。既有相关断言失败要调查修正，不能以“纯文案”为由跳过失败。

`make generate-api` 读取运行中后端并写生成文件。`check-openapi-generated.sh` 会启动
Compose 依赖和后端、写生成文件，并在退出时执行 `docker compose down`；必须先检查
目标项目、端口、已有服务和清理范围，使用隔离环境，不能当作纯静态检查。
`make staging` 会构建并启动容器、执行可写 Smoke，亦不是静态检查。

## 提交前门槛

[AGENTS.md](../../../AGENTS.md) 与[CONTRIBUTING](../../../CONTRIBUTING.md)采用上表的按影响检查。
纯文档执行文档验证；代码改动覆盖相关行为；跨域取并集，不将快速反馈等同完整交付验证。
容器、运行配置或集成链路变化时追加 `make staging` 或覆盖同等受影响路径的隔离集成检查，
明确选择依据、环境和断言。安全、权限、事务或并发行为不能只靠类型或编译通过验收。
环境受阻时报告未执行项目及原因，不把受阻等同通过；CI必需检查仍须按实际仓库配置满足。

## 专题与证据

- [前端测试](./frontend-testing.md)：组件、Hook、异步与隔离。
- [后端测试](./backend-testing.md)：领域、HTTP、真实数据库与事务。
- [E2E 与 Smoke](./e2e.md)：真实会话、数据和清理。
- [CI](./ci.md)：触发条件、状态、产物和本地检查的关系。
- [前端验收](../frontend/quality-guidelines.md)、[后端验收](../backend/quality-guidelines.md)：领域行为要求。

报告写实际命令、检出版本、范围、通过/失败/未运行、环境限制；不要用编译替代运行，
用截图存在替代目视检查，用旧提交结果替代当前修改。缺陷修复的测试应能区分修复前后行为。
