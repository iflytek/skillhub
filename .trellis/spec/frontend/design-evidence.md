# 设计审阅与证据留存

Figma 是可选辅助，默认不启用。仅当用户选择使用画板时，才应用本页的桥接操作要求；
未使用画板不影响直接按主题、组件与规范修改和验证前端，也不构成任务阻塞。
本页适用于通过 Figma 表达设计、评审页面或比较设计与实现的任务。
复用现有 Trellis 任务、正式 OpenSpec（若有）和[归档入口](../workflow/task-archive.md)。

## 分工与来源

- 设计库维护主题、组件与规则，按[设计系统采用](./design-system.md)读取。
- Figma 提供设计表达、组件实例、布局和审阅对象；记录具体文件与节点。
- React 源码维护真实交互、数据、权限和业务行为；浏览器验收验证运行结果。
- Figma 与设计库产生新差异时记录设计决定，并回写应维护的权威来源；不把两端都称作
  自动同步的单一事实。节点与组件的映射或导入截图也不等于行为实现。

## 工具与工作范围

用户选择 Figma 时使用 `$figma-web-bridge`，通过
`Agent → stdio MCP → WebSocket relay → 文件内插件 → Figma Plugin API` 操作。
Skill说明与真实服务连接分开检查；不能因官方Figma工具可见，就声称桥接已连接。

- 先读取该 Skill，发现实际暴露的 TalkToFigma 工具；不硬编码工具前缀或假设支持任意JS。
- 复用已有服务，获取本次 channel，再按实际 schema 加入并最小回读；通道不写入长期配置。
- 目标链接、节点与写入范围明确后再操作，不猜 file key/node ID，不因连接成功重做全文件。
- 先验证一个代表组件，再批量应用；保存返回的node ID，超时后先检查是否已写入再重试。
- 未连接时将画板步骤标为未执行，继续不依赖画板的工程工作。不自动安装服务、改防火墙，
  不自动调用官方Figma MCP作为回退；如用户后来明确改用其他方式，再核对相应授权与能力。

桥接仍受文件权限、插件运行、网络和本地超时影响；不承诺无限调用或已经消除全部限制。

现有站点捕获可用作视觉对照；可编辑组件、Auto Layout、变量绑定和可点击原型需分别
回读确认。不能仅上传整页截图就声称已经建立可复用的 Figma 设计系统。

## 轻量记录

已有任务时在任务记录中保存下列信息，不另建永久运行平台。任务摘要应包含：

| 项目 | 保存内容 |
|---|---|
| 设计输入 | 任务/正式需求、库版本与来源摘要、读取的主题/组件/规范 |
| Figma对象 | 实际文件URL、node ID、用途、读取/修改时间；未创建时写未创建 |
| 决策 | 已采用方案、人工修正及原因、设计库与图稿的差异和处理 |
| 实现 | 仓库版本、受影响文件、组件映射；未提交保持未提交状态 |
| 验证 | 命令、退出结果、浏览器/视口/主题、截图路径、实际审查结论 |
| 边界 | 未运行、失败、环境阻塞，以及后续动作 |

Figma链接是可变引用；需要固定证据时保存获准导出的截图/节点摘要和时间，并记录关联的
源码/契约摘要。任务中的个人截图和运行记录保持本地，收尾按既有归档流程保存到worktree外。

## 借鉴的门禁

1. 缺少实际来源、目标节点或输出时，不宣称已完成对应设计工作。
2. 文件写入、结构回读、视觉审查、原型交互、产品实现及业务验收分别给结论。
3. 校验后又改动了相关契约、图稿或代码，原通过结果不能证明新产物；仅重验受影响范围。
4. 失败保留输入、诊断、修正原因和复验结果，不通过覆盖旧报告或只改状态伪造完成。

这些要求借鉴设计工具的证据链与陈旧结果检查；不复制宿主专属 `.design` 格式、
画布渲染器或与本项目无关的调度账本。
